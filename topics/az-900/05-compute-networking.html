Describe Azure compute and networking services

Choose the right execution model, host, network path, and endpoint.

Domain 2 · Azure architecture and services · 35–40%AZ-900
In one minuteOfficial skillsCompute choicesAI, ML, and IoTVMs and hostingVirtual networkingEndpointsMCQsQuick recall

In one minute

  • Choose a VM when the scenario needs guest OS control or custom software; choose a container for portable app packaging; choose a function for short event-triggered code without server management.
  • Choose a scale set for VM fleet management and autoscale; choose an availability set for planned-maintenance or localized hardware-failure separation inside one datacenter; choose an availability zone for physically separate locations in one region.
  • Choose App Service when managed HTTP hosting fits; choose containers when the image is the deployment unit; choose a VM when customer-managed guest OS control is required.
  • Choose VPN Gateway when the requirement says encrypted over the public internet; choose ExpressRoute when it says private, dedicated, and not over the public internet.
  • Choose a private endpoint when the service needs a private VNet IP through Private Link; configure public network access separately if public access must be disabled.

AI, machine learning, and IoT/Edge

Azure AI services provide prebuilt language, speech, vision, and document APIs. Azure OpenAI Service supports governed generative-AI application scenarios. Use Azure Machine Learning to build, train, deploy, and manage custom machine-learning models.

Azure IoT Hub provides secure bidirectional device-to-cloud communication and device management. Azure IoT Central is a simplified SaaS IoT platform. Azure IoT Edge runs selected cloud workloads near devices for local processing and reduced latency or connectivity dependence.

ConfuseAI services = prebuilt APIs. Machine Learning = custom model lifecycle. IoT Hub = device communication/control. IoT Central = simplified SaaS IoT. IoT Edge = cloud workloads near devices.

VM options and application hosting

Virtual machine options

  • Azure virtual machine: single configurable VM. Choose size/series, image, disks, network, region, and resource group; manage guest OS and installed software.
  • Azure Virtual Machine Scale Sets: managed VM fleets with autoscale and centralized management. Uniform orchestration uses shared image/configuration; Flexible orchestration can mix VM types and Spot/on-demand instances. Scale sets still support scale and load-balanced app fleets.
  • Availability sets: place VMs across up to 3 fault domains and 20 update domains inside one datacenter. Only one update domain is restarted at a time; they reduce correlated maintenance or hardware failure, but do not protect against datacenter-level outages or provide zone separation.
  • Azure Virtual Desktop: desktop virtualization service delivering per-user Windows sessions or desktops. It is for user desktop/app access, not a general replacement name for VM scale-out.

Resources required for a VM

A VM deployment needs a size/series for CPU, memory, and capabilities; an image and OS disk; a region; a resource group; a network interface (NIC); and VNet/subnet context. Data disks, NSGs, public IPs, availability features, identity, monitoring, backup, and load balancing are optional design choices.

Common wrong turn

“An availability set protects against a datacenter or zone failure.” — It separates VMs across update and fault domains inside one datacenter; it does not protect against datacenter-level outages or provide zone separation.

Virtual networking and connectivity

An Azure virtual network (VNet) is a private logical network with an address space, subnets, routes, and network controls. A subnet divides that address space and gives resources a network segment. VNets and subnets span all availability zones in their region; do not create separate subnets solely for zones. VNet supports private Azure-resource, internet, and on-premises connectivity. Design address ranges before deployment; overlapping address spaces complicate peering and hybrid connectivity.

VNet peering connects VNets over Azure's network for private VNet-to-VNet traffic. It is non-transitive by default: if VNet A peers with B and B peers with C, A does not automatically reach C through B. Azure DNS provides name resolution and DNS hosting options for Azure and private networks. A public IP and public Load Balancer can provide inbound internet reachability and distribute traffic across healthy backends.

Network security groups (NSGs) allow or deny inbound and outbound traffic using source/destination IP, port, and protocol rules. Route tables and user-defined routes (UDRs) control subnet traffic paths. BGP can propagate on-premises routes through VPN Gateway, Route Server, or ExpressRoute. A network virtual appliance is a specialized VM for functions such as firewalling or WAN optimization.

Diagram: peering joins VNets privately; VPN Gateway and ExpressRoute provide distinct hybrid paths; private endpoint stays on a VNet IP.

ConnectionPathRemember
VPN GatewayEncrypted tunnel over the public internet between Azure and on-premises or another network.Site-to-site uses IPsec/IKE to an on-premises VPN device; point-to-site connects a remote client using OpenVPN, IKEv2, or SSTP; VNet-to-VNet uses IPsec/IKE between VPN gateways.
ExpressRoutePrivate dedicated connection through a connectivity provider; does not traverse the public internet.Predictable private path and enterprise connectivity. Standard circuits range from 50 Mbps to 10 Gbps; ExpressRoute Direct offers dual 10-, 100-, or 400-Gbps connectivity. It is not an encrypted-by-default internet VPN.

A route-based VPN gateway uses routing to select a tunnel and suits topology changes, point-to-site, VNet-to-VNet, multisite, and ExpressRoute coexistence. A policy-based gateway uses static traffic selectors. VPN gateways are active/standby by default; active/active uses two public IPs and can use BGP.

ConfusePeering connects VNets privately; VPN Gateway creates encrypted tunnels over public internet or related VPN paths; ExpressRoute provides private dedicated connectivity. Peering is not a replacement for every hybrid connection.
Common wrong turn

“VNet peering automatically carries traffic transitively through a third VNet.” — VNet peering is non-transitive by default, so A peered with B does not automatically reach C through B.

Exam clue“Private dedicated connection, no public internet” → ExpressRoute. “Encrypted tunnel over public internet” → VPN Gateway.

Endpoint choice is about network exposure, not whether a service is PaaS. Creating a private endpoint does not itself restrict public access: identity, RBAC, firewall, DNS, and service settings still matter.

MCQs

  1. Which compute type gives the customer guest operating-system control?
    • A. Function
    • B. Container
    • C. Virtual machine
    • D. App Service web app
    Answer

    Answer: C — Virtual machine.

    Reason: A VM exposes guest OS, installed software, and patching responsibilities.

    • A — Functions abstract the host and run code units.
    • B — Containers package apps and share a host kernel.
    • D — App Service manages the web hosting platform.
  2. A queue message should trigger short stateless code without server management. Which choice fits?
    • A. Function
    • B. Availability set
    • C. Virtual machine
    • D. ExpressRoute
    Answer

    Answer: A — Function.

    Reason: Functions are event-driven code units with provider-managed infrastructure.

    • B — Availability sets place VMs across fault and update domains.
    • C — A VM adds unnecessary host management.
    • D — ExpressRoute is a network connection.
  3. An application must package its runtime and dependencies consistently across hosts. Which unit is the best match?
    • A. Container image
    • B. Region pair
    • C. VPN tunnel
    • D. Availability set
    Answer

    Answer: A — Container image.

    Reason: Containers package an app and dependencies as a portable deployment unit.

    • B — Region pairs link geographic regions.
    • C — VPN tunnels connect networks.
    • D — Availability sets organize VM placement.
  4. Three VMs need protection from planned maintenance and localized hardware failure within one datacenter. Which option is intended?
    • A. Availability set
    • B. Availability zone
    • C. Scale set only
    • D. Private endpoint
    Answer

    Answer: A — Availability set.

    Reason: Availability sets separate VMs across update and fault domains within a datacenter.

    • B — Availability zones separate locations within a region.
    • C — Scale sets manage fleets and autoscale; they are not themselves a physical failure boundary.
    • D — Private endpoints provide private service connectivity.
  5. A design must spread VM instances across physically separate locations in one Azure region. What should it use?
    • A. Availability set
    • B. Availability zone
    • C. VM size
    • D. Azure DNS
    Answer

    Answer: B — Availability zone.

    Reason: Zones are physically separate locations inside a region.

    • A — Availability sets operate within one datacenter.
    • C — VM size controls compute capacity, not placement.
    • D — DNS resolves names and does not provide placement resilience.
  6. A web tier needs automatic instance-count changes and centralized VM fleet management. Which option is the best fit?
    • A. Virtual Machine Scale Sets
    • B. Availability set
    • C. Azure Files
    • D. Azure DNS
    Answer

    Answer: A — Virtual Machine Scale Sets.

    Reason: Scale sets manage VM fleets and can autoscale instance count.

    • B — Availability sets distribute placement but do not provide fleet autoscale.
    • C — Azure Files provides managed file shares.
    • D — Azure DNS provides name resolution and hosting.
  7. An enterprise requires an encrypted tunnel over the public internet from its office to Azure. Which service is designed for this path?
    • A. ExpressRoute
    • B. VPN Gateway
    • C. VNet peering
    • D. Private endpoint
    Answer

    Answer: B — VPN Gateway.

    Reason: VPN Gateway creates encrypted IPsec/IKE tunnel paths over the public internet.

    • A — ExpressRoute uses private dedicated provider connectivity.
    • C — VNet peering connects VNets over Azure's network, not office-to-Azure internet VPN.
    • D — Private endpoint connects privately to a service using a VNet IP.
  8. A regulated workload needs a private dedicated provider connection that does not traverse the public internet. Which choice fits?
    • A. VPN Gateway
    • B. ExpressRoute
    • C. Public endpoint
    • D. Service endpoint
    Answer

    Answer: B — ExpressRoute.

    Reason: ExpressRoute supplies private dedicated connectivity through a connectivity provider.

    • A — VPN Gateway uses encrypted tunnel paths, commonly over public internet.
    • C — Public endpoint is intentionally publicly reachable.
    • D — Service endpoint is a subnet-to-supported-service path, not a provider circuit.
  9. An Azure Storage account must be reached from a VNet using a private IP on a network interface. Which endpoint is this?
    • A. Public endpoint
    • B. Private endpoint
    • C. Availability set
    • D. Azure DNS zone pair
    Answer

    Answer: B — Private endpoint.

    Reason: Private Link private endpoints place a NIC with a private IP in the VNet.

    • A — Public endpoints use a public address path.
    • C — Availability sets place VMs.
    • D — DNS does not create a private service NIC.
  10. A team creates a private endpoint but leaves public network access enabled. What is the correct conclusion?
    • A. Public access is automatically disabled
    • B. Private endpoint and public access settings are separate decisions
    • C. The endpoint becomes an availability set
    • D. RBAC is no longer needed
    Answer

    Answer: B — Private endpoint and public access settings are separate decisions.

    Reason: Private endpoint adds a private path; identity, firewall, DNS, and public network settings still require configuration.

    • A — Creating the endpoint alone does not disable public access.
    • C — Endpoint type does not affect VM placement.
    • D — Network path does not replace authorization.

OS/data disks, VNet/subnet, NIC, controls, region, and resource group; optionally public IP.
