Describe cloud service types

IaaS, PaaS, SaaS, responsibility boundaries, and use-case signals.

Domain 1 · 25–30%AZ-900
In one minuteOfficial skillsThree service modelsUse casesResponsibility shiftServerlessMCQsQuick recall

In one minute

  • IaaS is the choice when guest OS, kernel, or low-level server control is required; customer patches the guest OS.
  • PaaS is the choice when the team deploys code but does not manage the guest OS or runtime; customer still manages code, data, identities, and configuration.
  • SaaS is the choice when a finished application meets the need; customer still manages users, data, access, and tenant settings.
  • Choose service type by control and operations burden: custom low-level control points to IaaS, custom code without OS work to PaaS, and ready-to-use software to SaaS.
  • Serverless is managed execution, not a fourth basic service type; servers exist and the provider operates them.

Official skills measured

Memorize wording. These are official objective bullets:

  • Describe infrastructure as a service (IaaS)
  • Describe platform as a service (PaaS)
  • Describe software as a service (SaaS)
  • Identify appropriate use cases for each cloud service type (IaaS, PaaS, and SaaS)

Three service models

As abstraction increases from IaaS to SaaS, Microsoft manages more of the stack and you manage less infrastructure. IaaS includes compute, storage, and networking; you always remain responsible for how you use the service, your data, identities, access, and configuration within the service.

Choose model from required control, operations burden, and whether a finished application already meets the need.

ConfuseIaaS vs PaaS boundary = who patches the OS? PaaS vs SaaS = do you deploy code? Serverless vs PaaS = event-triggered execution and granular billing versus continuously hosted app runtime; both reduce infrastructure work.
Common wrong turn

“SaaS means customer has no configuration or user work.” — SaaS provides finished software, but the customer still manages users, data, identities, access, tenant configuration, and business use.

Responsibility-shift stack

Read stack bottom to top. In IaaS, customer control reaches the OS; in PaaS, Microsoft manages through runtime; in SaaS, Microsoft manages the finished application. PaaS and SaaS application responsibility is shared: customer secures/configures code, data, and access they control; Microsoft operates service components.

Where serverless sits

Serverless sits beside or within the broader PaaS family of managed application platforms: Microsoft manages servers, OS, and platform; you provide code or workflow. It is not a fourth basic service type for this objective.

  • Often event-driven: HTTP request, queue message, timer, file event, or workflow trigger starts execution.
  • Provider handles host provisioning, patching, and capacity; customer focuses on function code, data, identity, and configuration.
  • Billing can follow invocations, execution time, memory, or workflow actions; suitable workloads may scale to zero.
  • Compared with general PaaS, serverless usually exposes less runtime/process control and emphasizes short-lived units, events, and granular execution scaling.
ConfuseServerless does not mean servers do not exist. It means you do not manage servers. Serverless can be PaaS-like, but not every PaaS app is serverless.
Memory hookMore abstraction → less infrastructure control: IaaS → PaaS → SaaS. Serverless = managed execution inside high-abstraction app hosting.

MCQs

  1. Which service type provides virtualized infrastructure while leaving guest OS management to you?
    • A. IaaS
    • B. PaaS
    • C. SaaS
    • D. Serverless workflow only
    Answer

    Correct: A — IaaS.

    Reason: IaaS provides compute, storage, and networking while you manage the guest OS and workload.

    B: Wrong because PaaS manages the OS and runtime.

    C: Wrong because SaaS is finished software.

    D: Wrong because a serverless workflow is not the IaaS service type.

  2. Which service type lets a team focus on application code while Microsoft manages the operating system and runtime?
    • A. IaaS
    • B. PaaS
    • C. SaaS
    • D. On-premises
    Answer

    Correct: B — PaaS.

    Reason: PaaS supplies managed application hosting and runtime without guest-OS control.

    A: Wrong because IaaS leaves guest OS maintenance with the customer.

    C: Wrong because SaaS supplies a finished application rather than an app deployment runtime.

    D: Wrong because on-premises leaves the physical platform with the organization.

  3. Which service type is a finished application that users configure and consume?
    • A. IaaS
    • B. PaaS
    • C. SaaS
    • D. Virtual network
    Answer

    Correct: C — SaaS.

    Reason: SaaS provides finished software while the provider operates its application and platform.

    A: Wrong because IaaS is infrastructure, not finished software.

    B: Wrong because PaaS is a managed app-hosting platform.

    D: Wrong because a virtual network is infrastructure, not an application service type.

  4. A team must install a custom kernel module on a migrated server. Which model is the best fit?
    • A. SaaS
    • B. PaaS
    • C. IaaS
    • D. Managed email
    Answer

    Correct: C — IaaS.

    Reason: IaaS provides the OS and low-level control needed for custom kernel software.

    A: Wrong because SaaS does not expose guest OS or kernel control.

    B: Wrong because PaaS abstracts the OS.

    D: Wrong because managed email is a finished application use case.

  5. A developer wants to deploy a custom web API but not patch servers or choose a guest OS. Which choice fits?
    • A. PaaS
    • B. IaaS
    • C. SaaS
    • D. Dedicated physical hosting managed by the team
    Answer

    Correct: A — PaaS.

    Reason: PaaS retains application-code control while Microsoft manages OS and platform layers.

    B: Wrong because IaaS requires customer guest-OS management.

    C: Wrong because SaaS is used as finished software rather than custom API deployment.

    D: Wrong because team-managed physical hosting preserves the maintenance burden being avoided.

  6. An organization wants ready-to-use collaboration software for employees, with tenant and user configuration only. Which model fits?
    • A. IaaS
    • B. PaaS
    • C. SaaS
    • D. Bare-metal hosting
    Answer

    Correct: C — SaaS.

    Reason: SaaS is appropriate for finished collaboration software consumed by users.

    A: Wrong because IaaS would require deploying and managing the application stack.

    B: Wrong because PaaS is for deploying custom applications.

    D: Wrong because bare-metal hosting adds infrastructure management rather than removing it.

  7. Which layer is customer-managed in IaaS but Microsoft-managed in PaaS?
    • A. Guest operating system
    • B. Customer data
    • C. Customer identities
    • D. Correct use of the service
    Answer

    Correct: A — Guest operating system.

    Reason: The IaaS customer patches the guest OS; PaaS provider manages OS and supported runtime.

    B: Wrong because customer data remains customer responsibility across models.

    C: Wrong because identities remain customer responsibility across models.

    D: Wrong because correct service use remains customer responsibility.

  8. Which discriminator most directly separates IaaS from PaaS?
    • A. Whether the provider has any physical datacenter
    • B. Whether the customer patches the guest OS
    • C. Whether users have identities
    • D. Whether data exists
    Answer

    Correct: B — Whether the customer patches the guest OS.

    Reason: Customer OS patching points to IaaS; Microsoft OS patching points to PaaS.

    A: Wrong because both IaaS and PaaS use provider physical infrastructure.

    C: Wrong because identities matter in every model.

    D: Wrong because data exists and remains customer responsibility in every model.

  9. Which statement correctly distinguishes PaaS from SaaS?
    • A. PaaS deploys customer application code; SaaS provides a finished application
    • B. PaaS requires customer physical datacenters; SaaS does not
    • C. PaaS never supports scaling; SaaS always exposes guest OS
    • D. PaaS is only for storage; SaaS is only for networking
    Answer

    Correct: A — PaaS deploys customer application code; SaaS provides a finished application.

    Reason: Deployment of custom code versus consumption of finished software is the key discriminator.

    B: Wrong because PaaS provider manages physical infrastructure.

    C: Wrong because PaaS supports scaling and SaaS does not expose guest OS.

    D: Wrong because these models describe application service abstraction, not those resource categories.

  10. Which description of serverless is accurate?
    • A. No servers exist anywhere
    • B. Customer patches the provider host after each event
    • C. Provider operates servers while customer supplies event-driven code or workflows
    • D. Serverless is a fourth basic service type that replaces SaaS
    Answer

    Correct: C — Provider operates servers while customer supplies event-driven code or workflows.

    Reason: Serverless removes server management and emphasizes event execution and granular scaling.

    A: Wrong because servers still exist.

    B: Wrong because provider handles host provisioning and patching.

    D: Wrong because serverless is a managed execution style, not a fourth basic type here.

Quick recall

Attempt each question before expanding it.

What does IaaS provide?

Virtualised infrastructure such as compute, storage, and networking while you manage the guest OS and workload.

What does PaaS provide?

Managed application hosting and runtime while you manage code, data, identities, and configuration.

What does SaaS provide?

Finished software that you use and configure while the provider operates the application and platform.

Who patches an IaaS guest OS?

Customer.

Who patches a PaaS OS and supported runtime?

Microsoft; customer maintains code and dependencies they own.

What remains customer responsibility in every model?

Data, identities, access, and correct use/configuration of the service.

Scenario: migrate a legacy server but keep full OS control. Which model?

IaaS.

Scenario: build a web app and focus on code, with no OS patching. Which model?

PaaS.

Scenario: give staff ready-to-use email and collaboration. Which model?

SaaS.

Scenario: custom kernel module required. Which model?

IaaS, because full OS/kernel control is required.

Where does serverless sit relative to PaaS?

It is a high-abstraction, managed execution style often considered PaaS-like; it emphasizes events and execution scaling.

What is fastest model discriminator?

OS patching: customer → IaaS; Microsoft → PaaS/SaaS. Deploy code? PaaS. Use finished product? SaaS.
