Microsoft Purview

Microsoft Purview provides unified data governance and compliance across a data estate. It helps an organization understand what data exists, where it lives, how it is classified, and how it moves.

  • Data map and catalog: maintain a searchable map of data sources and business metadata.
  • Discovery and classification: find data across the estate and identify sensitive or regulated information.
  • Lineage: trace data movement and transformation from source through downstream use.
  • Risk and compliance view: support governance decisions with visibility into data risks and compliance posture.
Exam cluePurview asks “What data do we have, where is it, and how is it governed?” It is a data governance and compliance view, not a resource deployment rule.

Azure Policy

Azure Policy defines what resource configuration is allowed or required. It evaluates resources against rules and can report, block, or remediate noncompliant configurations.

  • Audit: record noncompliance without blocking deployment.
  • Deny: prevent a request that violates policy.
  • deployIfNotExists: after resource-provider success, deploy a related configuration when required state is missing, subject to permissions and policy details.
  • modify: add, update, or remove resource properties or tags when the policy condition matches.
  • Initiatives: group related policy definitions into one assignment and compliance view.
  • Compliance dashboard: see compliance state, policy assignments, and noncompliant resources.
  • Scope and inheritance: assign at management group, subscription, resource group, or resource scope; assignment applies down the hierarchy unless excluded.

Policy examples

  • Allow resources only in approved regions.
  • Allow only approved VM SKUs.
  • Require tags such as department, environment, or owner.
  • Audit or deploy required diagnostic settings.
ConfusePolicy defines allowed or required configuration. RBAC defines who can perform actions. A person can have permission and still be blocked by policy if requested configuration is disallowed.

Resource locks

Resource locks protect Azure resources from accidental changes or deletion, including actions attempted by an owner. Apply a lock at subscription, resource group, or resource scope; child resources inherit the effective lock.

LockEffectRemoval
Delete (CanNotDelete in CLI/API)Resource can be read and changed, but cannot be deleted.Remove lock first, then perform blocked deletion.
Read-only (ReadOnly in CLI/API)Resource can be read but cannot be changed or deleted through blocked control-plane operations.Remove lock first, then perform blocked change or deletion.
  • Lock inheritance means a lock at a parent scope can protect child resources.
  • Locks are separate from permissions. Owner role does not automatically bypass a lock.
  • Locks apply only to Azure Resource Manager control-plane operations, not service data-plane operations.
  • Removing a lock requires Microsoft.Authorization/* or Microsoft.Authorization/locks/*; Owner and User Access Administrator have that access.
Exam clue“Protect production database from accidental deletion” → Delete (CanNotDelete) lock. “Prevent changes as well” → Read-only (ReadOnly) lock.
ConfuseLock vs RBAC deny: RBAC limits an identity’s allowed actions; lock protects resource state at scope, even from an otherwise authorized owner.

Microsoft Service Trust Portal

The Microsoft Service Trust Portal provides documents and resources describing Microsoft security, privacy, compliance controls, and processes. Some compliance material requires sign-in with a Microsoft Entra work or school account and acceptance of a non-disclosure agreement (NDA).

Exam clueService Trust Portal = Microsoft security, privacy, and compliance documentation; it is not Azure Policy or Microsoft Purview.

Governance toolkit decision list

  • Want to stop wrong region? → Azure Policy.
  • Want to stop accidental delete? → Resource Lock.
  • Want to limit a person? → RBAC.
  • Want cost reporting? → Tags.
Memory hookRBAC = actor permission. Policy = resource rule. Lock = emergency brake. Tag = label.

Related distinctions

Policy vs RBAC
Policy evaluates requested or existing resource configuration; RBAC evaluates identity permission to perform an action.
Lock vs RBAC deny
Lock protects a resource regardless of which authorized identity attempts the blocked operation; RBAC deny is identity and scope based.
Purview vs Policy
Purview discovers, catalogs, classifies, and traces data; Policy governs Azure resource configuration.
Initiative vs policy
Policy is one rule definition; initiative is a group of policy definitions assigned and reported together.

MCQs

  1. 1. Which governance tool evaluates whether a resource uses an approved region?
    • A. Azure Policy
    • B. RBAC
    • C. Microsoft Purview
    • D. Resource Lock
    Answer

    Correct: A — Azure Policy. Reason: Policy evaluates and can audit, deny, or remediate resource configuration.

    • B — RBAC evaluates who may perform an action.
    • C — Purview governs and classifies data across a data estate.
    • D — A lock blocks changes or deletion, not region configuration rules.
  2. 2. A developer has permission to create resources but must be prevented from deploying outside approved regions. What combination addresses both questions?
    • A. RBAC for permission and Azure Policy for region configuration
    • B. Resource Lock for permission and Purview for region configuration
    • C. Tags for permission and RBAC for region configuration
    • D. Purview for permission and Resource Lock for region configuration
    Answer

    Correct: A — RBAC for permission and Azure Policy for region configuration. Reason: RBAC answers who can act; Policy answers what configuration is allowed.

    • B — Locks protect state and Purview governs data, not these questions.
    • C — Tags label resources and RBAC does not validate region configuration.
    • D — Purview is not permission control, and locks are not region rules.
  3. 3. Which tool provides data discovery, classification, cataloging, and lineage?
    • A. Azure Policy
    • B. Microsoft Purview
    • C. Resource Lock
    • D. RBAC
    Answer

    Correct: B — Microsoft Purview. Reason: Purview provides unified data governance and compliance across the data estate.

    • A — Policy governs Azure resource configuration.
    • C — Locks protect resource state from changes or deletion.
    • D — RBAC grants actions to identities at scope.
  4. 4. A production resource group must not be deleted, even by an owner who has deletion permission. Which control fits?
    • A. Delete resource lock
    • B. Read-only Azure Policy
    • C. Purview classification
    • D. RBAC reader role
    Answer

    Correct: A — Delete resource lock. Reason: A CanNotDelete lock blocks deletion at scope, including an otherwise authorized owner’s attempt.

    • B — Policy does not provide a read-only lock effect.
    • C — Classification describes data, not resource deletion protection.
    • D — Reader permission is identity access, not a scope lock.
  5. 5. An initiative is assigned to a subscription. What does the initiative primarily represent?
    • A. One RBAC role assignment
    • B. A group of related policy definitions
    • C. One resource lock
    • D. A Purview data catalog
    Answer

    Correct: B — A group of related policy definitions. Reason: Initiatives bundle policies into one assignment and compliance view.

    • A — RBAC role assignments grant identity permissions.
    • C — A lock protects resource state.
    • D — A catalog is a Purview data-governance capability.
  6. 6. A security principal needs to create resources only inside one resource group. Which control expresses that scope?
    • A. RBAC
    • B. Azure Policy
    • C. Resource Lock
    • D. Microsoft Purview
    Answer

    Correct: A — RBAC. Reason: RBAC grants management actions to a principal at a chosen scope.

    • B — Policy evaluates resource configuration, not identity permission.
    • C — A lock blocks state changes or deletion.
    • D — Purview catalogs and classifies data.
  7. 7. A policy assignment at a management group affects a child resource group. Which concept explains this?
    • A. Policy inheritance down the scope hierarchy
    • B. Automatic tag inheritance
    • C. Purview lineage
    • D. Lock removal
    Answer

    Correct: A — Policy inheritance down the scope hierarchy. Reason: Policy assignments apply downward unless an exclusion changes effective scope.

    • B — Tags do not inherit by default.
    • C — Lineage traces data movement, not policy scope.
    • D — Removing a lock does not apply a policy assignment.
  8. 8. An administrator can change a resource but receives a deletion block from a CanNotDelete lock. What distinction is shown?
    • A. Lock protection is separate from RBAC permission.
    • B. Policy always grants delete permission.
    • C. Purview denies control-plane operations.
    • D. Tags create an authorization boundary.
    Answer

    Correct: A — Lock protection is separate from RBAC permission. Reason: A lock can block deletion even when the identity has permission to attempt it.

    • B — Policy does not grant identity permissions.
    • C — Purview is not the resource operation blocker here.
    • D — Tags do not grant or deny actions.
  9. 9. Which statement correctly contrasts an initiative with a policy?
    • A. Initiative is one rule; policy is many assignments.
    • B. Initiative groups policy definitions; policy defines one configuration rule.
    • C. Initiative protects deletion; policy catalogs data.
    • D. Initiative grants identity access; policy removes locks.
    Answer

    Correct: B — Initiative groups policy definitions; policy defines one configuration rule. Reason: An initiative bundles related policy definitions for assignment and compliance reporting.

    • A — The meanings are reversed.
    • C — Locks protect deletion, and Purview catalogs data.
    • D — RBAC grants access; neither initiative nor policy removes locks.
  10. 10. Which description of tags is correct in this governance comparison?
    • A. Tags answer who may perform an action.
    • B. Tags answer whether a resource can be deleted.
    • C. Tags label and support reporting on resources.
    • D. Tags classify and trace enterprise data lineage.
    Answer

    Correct: C — Tags label and support reporting on resources. Reason: Tags are name/value metadata for organization, filtering, and reporting.

    • A — RBAC answers who may act.
    • B — Resource locks protect against deletion.
    • D — Purview handles data classification and lineage.
