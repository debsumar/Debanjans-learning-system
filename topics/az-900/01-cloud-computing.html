Describe cloud computing

Cloud fundamentals: ownership, models, spending, and serverless.

Domain 1Describe cloud concepts25–30%
In one minuteOfficial skillsCloud computingShared responsibilityCloud modelsConsumption and pricingServerlessMCQsQuick recall

In one minute

  • Cloud computing is on-demand delivery over a network; it is not the same as owning peak-capacity hardware.
  • Shared responsibility shifts toward the provider as abstraction rises, but the customer always owns data, identities, and use.
  • Hybrid connects private or on-premises and public cloud; choose it when both boundaries must remain connected, not for multiple public providers.
  • Consumption pricing follows use, duration, tier, region, and features; it is flexible, not automatically cheaper without monitoring total cost.
  • Serverless removes customer server management and can bill per execution; servers still exist and the provider operates them.

What cloud computing is

Cloud computing = delivery of computing services over a network, on demand, with provider-operated infrastructure. Common rented capabilities include compute, storage, networking, and analytics:

Compute
Virtual machines, containers, functions, and managed app runtimes.
Storage
Durable objects, files, queues, tables, and disks.
Networking
Virtual networks, routing, load balancing, DNS, and connectivity.
Analytics
Managed processing, data platforms, reporting, and machine learning services.
KeyCloud changes procurement: provision resources when needed instead of buying every physical capacity requirement up front.
Memory hookCloud = rented capability plus provider-managed physical foundation.

Cloud models and use cases

Public cloud
Provider-owned shared infrastructure; customer resources are logically isolated. Fast scale, broad service choice, and no datacenter ownership.
Private cloud
Cloud environment dedicated to one organization, with cloud-like automation and self-service. Can be hosted on-premises or by a provider.
Hybrid cloud
Connected combination of private/on-premises and public cloud, allowing data or workloads to move across boundaries.

Diagram: public shares provider infrastructure, private dedicates an environment, and hybrid connects private/on-prem workloads to public cloud.

ModelGood fitTrade-off to remember
PublicNew apps, elastic traffic, global reach, managed services.Less physical control; shared provider platform.
PrivateStrict isolation, legacy constraints, dedicated control, regulated workloads.Organization still carries more capacity and operations burden.
HybridGradual migration, data residency, burst capacity, connected legacy systems.Integration, identity, networking, and operations become more complex.

Adjacent context: multicloud uses more than one public cloud provider. Azure Arc extends Azure management to resources outside Azure. Azure VMware Solution supports VMware workloads on dedicated Azure infrastructure. These ideas are related to hybrid operations but are not definitions of hybrid cloud.

ConfusePrivate cloud ≠ on-prem-only. Dedicated cloud can be provider-hosted. Hybrid ≠ multicloud: hybrid crosses private/on-prem and public; multicloud crosses cloud providers.
Common wrong turn

“Hybrid always means multiple public cloud providers.” — Hybrid crosses private or on-premises and public cloud. Multiple public providers describes multicloud instead.

Consumption-based model and pricing

Consumption-based model: pay for what you use, for how long, and for selected service tier or capacity. Provisioning is usually fast; cost follows usage and configuration.

ConceptRevision noteTypical signal
CapExUp-front capital expense for owned assets; value depreciates over time.Buy servers, storage, or datacenter equipment.
OpExOperating expense for ongoing services; easier to align spend with current use.Monthly cloud bill based on consumption.
Consumption pricingVariable bill changes with quantity, duration, transactions, tier, region, and features.Scale out increases spend; stop or release resource to reduce it.
Reservation / savings commitmentLower effective price in exchange for a committed term or usage pattern.Predictable steady workload.
  • Fixed pricing: predictable charge for a defined plan or capacity; simple budgeting, less elastic.
  • Variable pricing: follows actual consumption; flexible, but needs monitoring and guardrails.
  • Free tiers and credits: limited scope; check limits, expiry, and eligible services.
  • Total cost: include compute, storage, network egress, licenses, support, operations, and idle capacity.
ConfuseCapEx vs OpEx is an accounting and budgeting distinction, not “on-prem vs cloud” in every case. Cloud is commonly OpEx, but commitments and owned private-cloud equipment can change the pattern.
Common wrong turn

“Consumption pricing is always cheaper.” — Consumption pricing is flexible, but its bill changes with use and configuration. Total cost still includes compute, storage, network egress, licenses, support, operations, and idle capacity.

Exam clue“Pay only when running” points to consumption-based pricing. “Long, stable workload” points toward a commitment or reservation comparison.

Serverless

Serverless is an execution model where the provider provisions and operates servers; customer supplies code or workflow and pays for execution or operations. Servers still exist.

  • Event-driven: trigger from HTTP, a message, timer, file, or other event.
  • No server management: no VM patching, capacity planning, or host administration.
  • Pay per execution: cost tracks invocations, execution time, memory, or workflow actions.
  • Scales to zero: suitable workloads can have no running instances between events, subject to plan and service behavior.
Azure Functions style Small code units run in response to events. Good for APIs, timers, queues, and automation.
Logic Apps style Designer-based workflow orchestration using triggers and connector actions.

Serverless vs PaaS: both reduce infrastructure management. PaaS commonly gives a continuously hosted application runtime with more control over app process and scaling; serverless emphasizes event-triggered units or workflows, granular execution billing, and scale-to-zero behavior.

ConfuseServerless ≠ “no servers exist.” It means customer does not manage servers. PaaS ≠ serverless: managed app hosting can still run as a continuously available process.
Memory hookServerless = send event, run function, pay execution; provider handles host.

MCQs

  1. Which phrase best defines cloud computing?
    • A. Buying peak-capacity hardware for a private datacenter
    • B. On-demand delivery of computing services over a network
    • C. Installing only desktop software on local devices
    • D. Running applications without any physical servers
    Answer

    Correct: B — On-demand delivery of computing services over a network.

    Reason: Cloud computing delivers provider-operated computing capabilities when needed.

    A: Wrong because it describes owned capacity, not on-demand cloud delivery.

    C: Wrong because cloud includes compute, storage, networking, and more.

    D: Wrong because physical servers still exist and are operated by providers.

  2. In every cloud service model, which responsibility remains with the customer?
    • A. Physical datacenter cooling
    • B. Provider host firmware
    • C. Information and data
    • D. Hypervisor patching
    Answer

    Correct: C — Information and data.

    Reason: The customer owns data, identities, and correct use of the service in every model.

    A: Wrong because the provider manages physical datacenter operations.

    B: Wrong because host firmware is part of the provider foundation.

    D: Wrong because the provider manages virtualization infrastructure.

  3. Which model uses provider-owned shared infrastructure with logical isolation between customers?
    • A. Public cloud
    • B. Private cloud
    • C. Hybrid cloud
    • D. On-premises only
    Answer

    Correct: A — Public cloud.

    Reason: Public cloud shares provider infrastructure while isolating customer resources logically.

    B: Wrong because private cloud is dedicated to one organization.

    C: Wrong because hybrid connects private or on-premises and public environments.

    D: Wrong because on-premises does not describe provider-owned shared cloud infrastructure.

  4. A company must keep a legacy database on-premises while bursting web capacity into Azure. Which cloud model fits?
    • A. Public
    • B. Private
    • C. Hybrid
    • D. SaaS
    Answer

    Correct: C — Hybrid.

    Reason: Hybrid connects private or on-premises workloads with public cloud capacity.

    A: Wrong because public alone does not include the retained on-premises workload.

    B: Wrong because private alone does not provide the public burst environment.

    D: Wrong because SaaS is a service type, not this deployment model.

  5. A team wants a finished customer relationship application and does not want to deploy code. Which choice is most appropriate?
    • A. Private cloud
    • B. Public cloud
    • C. IaaS virtual machine
    • D. SaaS application
    Answer

    Correct: D — SaaS application.

    Reason: SaaS provides finished software that the customer configures and uses.

    A: Wrong because private cloud describes deployment, not finished application consumption.

    B: Wrong because public cloud describes ownership and sharing, not the application abstraction.

    C: Wrong because IaaS requires the team to operate more of the workload stack.

  6. A predictable long-running workload needs a lower effective price in exchange for a term commitment. Which pricing idea should be compared?
    • A. Reservation or savings commitment
    • B. Free tier only
    • C. Unmonitored variable pricing
    • D. Physical depreciation only
    Answer

    Correct: A — Reservation or savings commitment.

    Reason: A commitment can lower effective price for a stable usage pattern.

    B: Wrong because free tiers are limited and are not a general stable-workload commitment.

    C: Wrong because variable pricing follows use but does not provide the stated commitment trade-off.

    D: Wrong because depreciation describes owned assets and CapEx, not this cloud pricing choice.

  7. Which statement distinguishes CapEx from OpEx?
    • A. CapEx is always public cloud and OpEx is always private cloud
    • B. CapEx is up-front spending on owned assets; OpEx is ongoing service spending
    • C. CapEx means serverless and OpEx means virtual machines
    • D. CapEx is data ownership and OpEx is identity ownership
    Answer

    Correct: B — CapEx is up-front spending on owned assets; OpEx is ongoing service spending.

    Reason: CapEx and OpEx are accounting and budgeting distinctions.

    A: Wrong because deployment model does not make the accounting distinction absolute.

    C: Wrong because service type does not define CapEx or OpEx.

    D: Wrong because responsibilities are unrelated to this accounting distinction.

  8. A function should run when a queue message arrives, with no VM patching and payment tied to execution. Which approach fits?
    • A. Serverless
    • B. Private cloud hardware purchase
    • C. Dedicated physical server administration
    • D. Fixed-capacity on-premises cluster
    Answer

    Correct: A — Serverless.

    Reason: Serverless is event-driven, provider-operated, and commonly billed by execution.

    B: Wrong because buying hardware leaves server operations with the customer.

    C: Wrong because serverless removes host administration from the customer.

    D: Wrong because a fixed cluster does not express event-driven execution and scale to zero.

  9. Which comparison is correct?
    • A. Hybrid means multiple public providers; multicloud means private plus public
    • B. Private cloud must be on-premises only
    • C. Serverless means no servers exist
    • D. Hybrid crosses private or on-premises and public boundaries; multicloud uses multiple cloud providers
    Answer

    Correct: D — Hybrid crosses private or on-premises and public boundaries; multicloud uses multiple cloud providers.

    Reason: The terms describe different boundaries.

    A: Wrong because it reverses the definitions.

    B: Wrong because a private cloud can be provider-hosted.

    C: Wrong because servers exist; the provider manages them.

  10. A team wants event-triggered code with scale-to-zero behavior, while another team needs a continuously hosted app runtime. Which distinction is most accurate?
    • A. Both are exactly the same pricing and execution model
    • B. Serverless emphasizes event execution and granular billing; PaaS commonly hosts an application runtime continuously
    • C. PaaS always requires customer physical servers
    • D. Serverless requires customer OS patching
    Answer

    Correct: B — Serverless emphasizes event execution and granular billing; PaaS commonly hosts an application runtime continuously.

    Reason: Both reduce infrastructure management, but serverless emphasizes event units and scale to zero.

    A: Wrong because their execution and billing emphasis differs.

    C: Wrong because PaaS is provider-managed infrastructure.

    D: Wrong because serverless removes customer server and OS management.
