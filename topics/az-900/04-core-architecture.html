Describe the core architectural components of Azure

Geography, availability, and the Azure resource hierarchy.

Domain 2Azure architecture and services35–40%
In one minuteOfficial skillsAzure accountsGeography and availabilityResource hierarchyScope guideMCQsQuick recall

In one minute

  • Physical topology runs datacenter → availability zone → region → region pair → geography; each step changes failure or residency scope.
  • Availability zones isolate facility failures within one region; region pairs link regions but do not by themselves guarantee failover.
  • Subscription is the billing, quota, limits, and access boundary; it contains resource groups.
  • Resource groups organize related resources for lifecycle; they are flat, can span regions, and deletion deletes their contents.
  • Management groups contain subscriptions so policy and role assignments can inherit downward; resources are the leaf service instances.

Azure accounts and offers

An Azure account can create multiple subscriptions. Teams commonly separate development, test, production, and sandbox workloads by subscription for billing, access, quotas, and governance boundaries. An account is not the same as a subscription: the account establishes identity and billing context; subscriptions contain resource groups and resources.

  • Free Azure account: limited credit and selected free services for eligible users; check expiry, quotas, and service limits.
  • Azure for Students: eligible students receive a credit-based offer with restrictions and expiry.
  • Monitor offer usage and remove unused resources; free credits do not make every service or usage pattern free.
Exam clueAccount → subscriptions → resource groups → resources. Separate dev/test/prod when billing, access, quotas, or governance must differ.

Azure geography and availability

Think physical topology from smallest to largest: datacenter → availability zone → region → region pair → geography. A datacenter is a facility; a zone is an isolated grouping of one or more datacenters; a region is a geographic area containing Azure datacenters; a region pair links two regions; a geography is a broad market or data-residency boundary.

Diagram: datacenters sit inside availability zones; zones sit inside one region.

Region pairs

Some Azure regions are paired. Pairing supports selected service-specific geo-replication, recovery sequencing, and staggered platform updates: when possible, one region is updated before its partner. Pairing does not itself provide automatic high availability, disaster recovery, replication, or failover; configure service-specific redundancy.

Sovereign and special regions

Azure Government regions support US government requirements. Azure operated by 21Vianet provides Azure in China. These are isolated instances with separate compliance, operations, and connectivity considerations, not merely another choice inside global commercial Azure.

Availability zones

Availability zones are physically separate locations within an Azure region, each with one or more datacenters and independent power, cooling, and networking. Services may use different subsets of zones; do not assume a universal zone count. A zone-resilient resource uses two or more zones. Zonal resources are pinned to one zone. Zone-redundant services spread replicas across zones so a zone failure need not take out the service. A region can have zones; a region pair is a relationship between regions. They solve different failure scopes.

ConfuseRegion = geographic area containing datacenters; region pair = two linked regions; availability zone = physically separate location inside one region. Zone failure scope stays within one region; region pair supports cross-region continuity considerations.
Common wrong turn

“A region pair automatically provides failover for every service.” — Pairing supports selected service-specific geo-replication, recovery sequencing, and updates. It does not itself guarantee high availability, disaster recovery, replication, or failover.

Exam clueNeed protection from one datacenter location failing inside a region? Think availability zones. Need regional disaster or regional service continuity? Think region pairs and service redundancy.
Memory hookZone = nearby isolation; pair = far-away partner. “Zonal” chooses one; “zone-redundant” spans zones.

Azure resource hierarchy

Management scope descends as management group → subscription → resource group → resource. Policies and role assignments can flow downward through this hierarchy.

Diagram: governance scope flows downward; each arrow marks a narrower management boundary.

Resource
Manageable Azure item: VM, storage account, virtual network, database, or other service instance. A resource belongs to one resource group.
Resource group
Logical, flat container for related resources and their lifecycle. Resource groups cannot nest. A resource can belong to only one resource group, while one resource group can contain many resources. Deleting the resource group deletes its contents.
Subscription
Billing and access boundary. Holds resource groups, has service limits and quotas, and is a common unit for cost, governance, and environment separation.
Management group
Container for subscriptions. One directory has one hierarchy: up to 10,000 management groups and six management-group levels excluding root and subscription. The Tenant root group contains all groups and subscriptions; no default access exists, and root assignments inherit to descendants.
ConfuseSubscription ≠ resource group ≠ management group. Subscription pays and sets an access boundary; resource group organizes resource lifecycle; management group organizes subscriptions and governance.
ConfuseResource group is not a location boundary. Resources inside one resource group can use different regions. Group resources together for lifecycle and management, not because they must share a datacenter.
Common wrong turn

“A resource group is a billing boundary.” — Subscription is the billing and access boundary with quotas and limits. Resource group is a logical lifecycle container for related resources.

  1. 1. Management group

    Set policy and role assignments across subscriptions. These settings can inherit downward through the hierarchy.

  2. 2. Subscription

    Set billing, quotas, limits, access, and environment separation at subscription scope. It contains resource groups and receives applicable settings from above.

  3. 3. Resource group

    Set lifecycle and operational grouping for related resources. It is flat and non-nesting; applicable policy and permissions continue downward.

  4. 4. Resource

    Manage one deployable Azure service instance. It receives direct settings or inherited policy and permissions from its scopes.

MCQs

  1. Which Azure scope directly contains resource groups?
    • A. Management group
    • B. Subscription
    • C. Resource
    • D. Region pair
    Answer

    Answer: B — Subscription.

    Reason: Subscriptions contain resource groups and provide billing, quotas, and access boundaries.

    • A — Management groups contain subscriptions.
    • C — Resources sit inside resource groups.
    • D — Region pairs link regions and are not resource hierarchy scopes.
  2. A team wants one policy to govern six production subscriptions. Which scope is the best starting point?
    • A. Resource
    • B. Resource group
    • C. Management group
    • D. Availability zone
    Answer

    Answer: C — Management group.

    Reason: Management groups organize subscriptions and allow governance to flow downward.

    • A — Resource scope is too narrow.
    • B — Resource groups organize resources within one subscription.
    • D — Availability zones are physical resiliency locations.
  3. What happens when an Azure resource group is deleted?
    • A. Only its tags are removed
    • B. Its contained resources are deleted
    • C. Its subscription is deleted
    • D. Its resources move to the tenant root group
    Answer

    Answer: B — Its contained resources are deleted.

    Reason: A resource group is a lifecycle container, so deletion removes its contents.

    • A — Tags are not the lifecycle boundary.
    • C — A resource group does not contain subscriptions.
    • D — Resources are not automatically reparented.
  4. Two resources in one resource group must use different Azure regions. Is that allowed?
    • A. No; resource groups are region boundaries
    • B. Yes; resource groups are logical lifecycle containers
    • C. Only when the resources are in one availability zone
    • D. Only inside a management group
    Answer

    Answer: B — Yes; resource groups are logical lifecycle containers.

    Reason: A resource group is not a location boundary; contained resources can use different regions.

    • A — Region placement is separate from resource-group membership.
    • C — Zones are inside regions and do not impose this rule.
    • D — Management groups contain subscriptions, not regional resources.
  5. A database must remain available if one availability zone fails, while staying in the same region. Which design distinction matters?
    • A. Zone-redundant deployment
    • B. Region pair only
    • C. Management group nesting
    • D. Resource-group deletion
    Answer

    Answer: A — Zone-redundant deployment.

    Reason: Zone redundancy spreads replicas across physically separate zones within one region.

    • B — A region pair addresses a relationship between regions, not one zone failure by itself.
    • C — Management groups are governance scopes.
    • D — Deletion is destructive lifecycle behavior, not availability design.
  6. Which statement best distinguishes a region pair from an availability zone?
    • A. A region pair is inside one datacenter
    • B. A zone links two geographies
    • C. A region pair links two regions; a zone is inside one region
    • D. They are two names for the same boundary
    Answer

    Answer: C — A region pair links two regions; a zone is inside one region.

    Reason: Their failure scopes differ: zones isolate facilities within a region, while pairs connect regions.

    • A — A zone can contain datacenters; a pair is not inside one datacenter.
    • B — A zone does not link geographies.
    • D — They solve different topology problems.
  7. An administrator needs a billing and quota boundary for a dev environment. Which object fits?
    • A. Subscription
    • B. Resource group
    • C. Datacenter
    • D. Availability zone
    Answer

    Answer: A — Subscription.

    Reason: Subscription is the common billing, quota, limits, and access boundary.

    • B — Resource groups organize lifecycle, not broad billing boundaries.
    • C — Datacenters are physical facilities.
    • D — Zones are resiliency locations inside regions.
  8. A company wants to delete an application and all its dependent Azure resources together. What should hold them?
    • A. A resource group
    • B. A region pair
    • C. A management group level
    • D. A tenant root group
    Answer

    Answer: A — A resource group.

    Reason: Resource groups provide lifecycle grouping and deleting one deletes contained resources.

    • B — Region pairs are geographic relationships.
    • C — Management groups contain subscriptions, not application resources directly.
    • D — Tenant root group is the top governance group.
  9. Which object can contain multiple subscriptions and receive governance inherited by them?
    • A. Resource
    • B. Resource group
    • C. Management group
    • D. Availability zone
    Answer

    Answer: C — Management group.

    Reason: Management groups are subscription containers in the governance hierarchy.

    • A — Resources are the leaf items.
    • B — Resource groups sit below subscriptions.
    • D — Zones are physical locations, not governance containers.
  10. Which statement about Azure region pairs is correct?
    • A. Pairing alone guarantees automatic failover for every service
    • B. Pairing is selected service-specific support for geo-replication and recovery sequencing
    • C. Pairing places all resources in three zones
    • D. Pairing replaces the need to configure redundancy
    Answer

    Answer: B — Pairing is selected service-specific support for geo-replication and recovery sequencing.

    Reason: Pairing can support replication and sequenced updates, but service configuration still determines protection.

    • A — Pairing itself does not guarantee failover.
    • C — Zones are within regions and are separate from pairing.
    • D — Redundancy and failover must be configured per service.

Quick recall

Attempt each question before expanding it.

What is the hierarchy?

Management group → subscription → resource group → resource.

What does a region represent?

Geographic area containing Azure datacenters and services.

What is an availability zone?

Physically separate location inside a region, with independent power, cooling, and networking.

What does zone-redundant mean?

Service replicas span multiple availability zones.

What does a region pair provide?

Some regions are paired for selected service-specific geo-replication, recovery sequencing, and staggered updates; pairing does not itself guarantee HA, DR, replication, or failover.

What are sovereign regions?

Isolated Azure instances such as US Government and Azure operated by 21Vianet in China.

Can resource groups nest?

No. They are flat containers.

What happens when a resource group is deleted?

Its contained resources are deleted.

What is a subscription?

Billing and access boundary with quotas and limits.

Are resources in one resource group forced into one region?

No. Resource group is not a location boundary.
