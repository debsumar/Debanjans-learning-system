Terms

Analytics
Managed processing, data platforms, reporting, and machine learning services. Chapter context
Application Insights
Application performance monitoring (APM): request rates, response times, failures, dependency tracking, availability tests, and usage analytics. Chapter context
Azure Monitor alerts
Rules triggered by metric, log, or activity-log conditions; send through action groups to email, SMS, webhook, automation, and other actions, with severity. Chapter context
Azure Status
Global public view of Azure service status; Service Health is personalized to your services, subscriptions, and relevant events. Chapter context
Budgets and alerts
Budgets and alerts provide spend guardrails; Advisor provides personalised cost recommendations. Chapter context
Compute
Virtual machines, containers, functions, and managed app runtimes. Chapter context
Hybrid cloud
Connected combination of private/on-premises and public cloud, allowing data or workloads to move across boundaries. Chapter context
Log Analytics workspace
Central workspace for collecting and querying log data with KQL (Kusto Query Language). Chapter context
Logs
Queryable records and events: activity, diagnostics, application traces, errors, and structured telemetry. Chapter context
Management group
Container for subscriptions. One directory has one hierarchy: up to 10,000 management groups and six management-group levels excluding root and subscription. The Tenant root group contains all groups and subscriptions; no default access exists, and root assignments inherit to descendants. Chapter context
Metrics
Numeric time series measured over time: CPU percentage, request count, latency, availability, or memory. Chapter context
MFA
Require two or more factors: something you know, something you have, or something you are. A password plus authenticator approval is stronger than password alone. Chapter context
Networking
Virtual networks, routing, load balancing, DNS, and connectivity. Chapter context
Passwordless
Authenticate without a password using methods such as Windows Hello, authenticator app, or FIDO2 security keys. Passwordless is not the same as MFA, though a passwordless method can use multiple factors. Chapter context
Patching
Managed services and provider-operated layers can reduce customer patching work. Customer remains responsible for layers they control, such as an IaaS guest OS. Chapter context
Policy auditing
Governance policies inspect or enforce requirements such as allowed locations, required tags, encryption settings, or permitted resource types. Chapter context
Pricing Calculator
Pricing Calculator is used before deployment; Microsoft Cost Management is used for actual spend. Chapter context
Private cloud
Cloud environment dedicated to one organization, with cloud-like automation and self-service. Can be hosted on-premises or by a provider. Chapter context
Provider hardening
Provider security teams, physical controls, baseline protections, threat intelligence, and platform investment benefit every tenant within shared-responsibility limits. Chapter context
Public cloud
Provider-owned shared infrastructure; customer resources are logically isolated. Fast scale, broad service choice, and no datacenter ownership. Chapter context
Resource
Manageable Azure item: VM, storage account, virtual network, database, or other service instance. A resource belongs to one resource group. Chapter context
Resource group
Logical, flat container for related resources and their lifecycle. Resource groups cannot nest. A resource can belong to only one resource group, while one resource group can contain many resources. Deleting the resource group deletes its contents. Chapter context
SSO
Sign in once, then access multiple trusted applications without a separate sign-in to each one. Chapter context
Storage
Durable objects, files, queues, tables, and disks. Chapter context
Subscription
Billing and access boundary. Holds resource groups, has service limits and quotas, and is a common unit for cost, governance, and environment separation. Chapter context
Tags
Tags provide cross-cutting metadata and reporting; resource groups provide lifecycle organization. Chapter context
TCO Calculator
TCO Calculator compares on-premises and Azure total cost. Chapter context
Templates
Infrastructure templates or blueprint-style patterns repeat approved configurations, reducing drift and one-off mistakes. Chapter context

Discriminators

These contrast two confusable things rather than define one.

Application Insights vs Log Analytics
Application Insights is application-focused APM and instrumentation; its telemetry can be stored and queried through Azure Monitor and Log Analytics. Chapter context
Arc vs Migrate
Arc manages external resources in place; Migrate helps assess and move workloads to Azure. Chapter context
ARM vs ARM template
ARM is the management and deployment control plane; an ARM template is a declarative JSON deployment definition. Chapter context
CLI vs PowerShell
CLI uses az commands and is shell-friendly across platforms; PowerShell uses Az cmdlets and object pipelines. Chapter context
Cloud Shell vs CLI
Cloud Shell is a browser-hosted, pre-authenticated environment; CLI is a command-line tool that can run there or locally. Chapter context
Initiative vs policy
Policy is one rule definition; initiative is a group of policy definitions assigned and reported together. Chapter context
Lock vs RBAC deny
Lock protects a resource regardless of which authorized identity attempts the blocked operation; RBAC deny is identity and scope based. Chapter context
Log Analytics vs Azure Monitor
Log Analytics is the workspace and query experience for logs; Azure Monitor is the broader telemetry platform containing metrics, logs, alerts, dashboards, and integrations. Chapter context
Policy vs RBAC
Policy evaluates requested or existing resource configuration; RBAC evaluates identity permission to perform an action. Chapter context
Portal vs template
Portal is visual and useful for exploration or one-off work; template is repeatable, reviewable, and automation-friendly. Chapter context
Purview vs Policy
Purview discovers, catalogs, classifies, and traces data; Policy governs Azure resource configuration. Chapter context
Service Health vs Resource Health
Service Health is the broader personalized view of Azure service issues, maintenance, and advisories; Resource Health focuses on availability and health of one resource. Chapter context
