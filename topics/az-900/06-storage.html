Azure Storage services

Start with data shape and access protocol. Storage account settings then add performance, region, redundancy, security, and endpoint decisions.

ServiceWhat it storesPick this when
Blob StorageUnstructured object data: documents, images, video, backups, logs, and data lake content.Need massive object storage, HTTP-based access, metadata, or lifecycle tiering.
Azure FilesManaged file shares over SMB or NFS.Need shared folders, lift-and-shift file servers, or familiar file-share access from cloud/on-prem clients.
Queue StorageMessages for asynchronous work between components.Need simple durable work backlog or producer/consumer decoupling.
Table StorageNoSQL key-value entities with partition and row keys.Need schemaless structured data with simple key-based access at scale.
Managed disksBlock storage volumes attached to Azure VMs.Need VM OS disks or persistent VM data disks.
ConfuseBlob ≠ Files. Blob is object storage accessed as objects; Azure Files is managed shared file storage with SMB/NFS semantics. A file extension does not decide the service.
Memory hookBlob = objects; Files = folders; Queue = messages; Table = entities; Disk = VM block volume.

Access tiers and lifecycle

Blob access tiers trade storage price against access cost and availability. Use lifecycle management to move objects automatically based on age or conditions.

TierPatternCost shape
HotFrequently accessed data.Higher storage cost, lower access cost.
CoolInfrequently accessed data kept online.Lower storage cost, higher access cost; 30-day minimum.
ColdRarely accessed data that still needs online availability.Lower storage cost than cool, higher access cost; 90-day minimum.
ArchiveVery rarely accessed offline blob data.Lowest storage cost, highest access cost, 180-day minimum, and rehydration latency before reading.
Smart tierEligible blobs move among hot, cool, and cold based on usage.Automatic tier selection; review service and blob eligibility.

Archive is offline: rehydrate to hot, cool, or cold before normal reads; rehydration can take up to 15 hours. Do not choose archive for interactive data. Lifecycle management can transition hot → cool → cold → archive, or delete data after retention rules.

ConfuseCool and cold are online. Archive is offline and needs rehydration. “Cheaper storage” does not mean “cheaper to read.”
Exam clueFrequent reads → hot. Infrequent but immediately available → cool or cold. Long-term rarely read and delay is acceptable → archive.

Redundancy options

Redundancy copies data according to failure scope. Select the account redundancy that matches durability, availability, residency, and cost requirements.

Diagram: redundancy scope grows from one datacenter to zones, then to asynchronous paired-region protection.

OptionCopies / scopeSurvives
LRS3 copies in one datacenter.Disk or rack/device failure in that location; not a zone or region outage.
ZRSSynchronous copies across 3 or more zones in one region.Availability zone failure; not a full regional outage.
GRS3 LRS primary copies plus 3 asynchronous LRS secondary copies in another region.Primary region outage at the secondary copy level; secondary can lag and account failover is required to restore write availability.
GZRS3 or more zonal primary copies plus 3 asynchronous LRS secondary copies in another region.Zone failure in primary and regional failure through secondary replication.
RA-GRS / RA-GZRSRead-access variants of GRS / GZRS.Allow reads from secondary while primary is available; secondary can lag.
ConfuseZRS protects across zones in one region. GRS protects with a secondary region. GZRS combines zone redundancy in primary with geo-replication. Geo failover can lose unreplicated writes and is needed to restore writes after primary-region loss.

Storage account basics

  • Name: globally unique Azure-wide, 3–24 characters, lowercase letters and numbers only.
  • Endpoint: service address for blob, file, queue, or table access.
  • Types: Standard GPv2 is recommended for most scenarios; premium account types are block blobs, file shares, and page blobs. GPv1 and legacy Blob Storage accounts are legacy; classic ASM is retired.
  • Region: deployment location and data-residency choice.
  • Redundancy: selected per account, subject to service and region support.

One account can expose multiple storage services, but account-level choices constrain the options available to data inside it. Security and access still require identity, keys/SAS where applicable, network rules, and least privilege.

Move files and migrate workloads

ToolWhat it doesUse it when
AzCopyCommand-line copy and sync utility for Azure Storage.Need scripted, repeatable, high-volume file/object transfer or synchronization.
Azure Storage ExplorerGUI for browsing and managing storage data and accounts.Need interactive inspection, upload/download, or administration without command syntax.
Azure File SyncSyncs an on-premises Windows file server with Azure Files and supports cloud tiering.Keep local file-server access while centralizing data in Azure Files and tiering less-used files.
Azure MigrateDiscovery, assessment, and migration hub for servers, workloads, and applications.Plan and execute broader datacenter/workload migration, not merely copy a folder.
Azure Data BoxPhysical appliance for offline transfer of very large datasets to Azure.Network bandwidth or transfer time makes online movement impractical; ship data on appliance.
ConfuseData Box vs AzCopy: Data Box ships a physical appliance for bandwidth-bound bulk transfer; AzCopy uses network connectivity for CLI copy/sync. Azure Migrate assesses and moves workloads; it is not just a file-copy command.
Exam clueOn-prem Windows file server plus Azure Files and cloud tiering → Azure File Sync. Huge offline dataset → Data Box. Migration discovery and assessment → Azure Migrate.

MCQs

  1. Which Azure Storage service is designed for unstructured object data such as images and logs?
    • A. Blob Storage
    • B. Azure Files
    • C. Queue Storage
    • D. Managed disks
    Answer

    Answer: A — Blob Storage.

    Reason: Blob Storage stores unstructured objects and supports HTTP-based access and tiering.

    • B — Azure Files provides managed file shares.
    • C — Queue Storage stores messages.
    • D — Managed disks provide VM block volumes.
  2. A legacy application expects an SMB shared folder mounted by several clients. Which service fits?
    • A. Blob Storage
    • B. Azure Files
    • C. Table Storage
    • D. Archive tier
    Answer

    Answer: B — Azure Files.

    Reason: Azure Files provides managed SMB or NFS file shares.

    • A — Blob Storage is object storage, not folder-share semantics.
    • C — Table Storage stores key-value entities.
    • D — Archive is a blob access tier, not a file-share service.
  3. Which blob tier is offline and requires rehydration before normal reads?
    • A. Hot
    • B. Cool
    • C. Cold
    • D. Archive
    Answer

    Answer: D — Archive.

    Reason: Archive minimizes storage cost for rarely accessed blobs but requires rehydration.

    • A — Hot is for frequent access.
    • B — Cool remains online with higher access cost.
    • C — Cold remains online for rare access.
  4. A storage account must survive an availability-zone failure while keeping data in one region. Which redundancy option is the direct match?
    • A. LRS
    • B. ZRS
    • C. GRS
    • D. Data Box
    Answer

    Answer: B — ZRS.

    Reason: ZRS synchronously copies data across three or more zones in one region.

    • A — LRS keeps copies in one datacenter.
    • C — GRS adds a paired region and is not the one-region-only choice.
    • D — Data Box is a transfer appliance.
  5. A company needs protection from a primary-region outage and accepts asynchronous secondary copies. Which option fits?
    • A. LRS
    • B. ZRS
    • C. GRS
    • D. Cool tier
    Answer

    Answer: C — GRS.

    Reason: GRS replicates primary LRS copies asynchronously to a paired secondary region.

    • A — LRS has one-datacenter scope.
    • B — ZRS stays within one region.
    • D — Cool changes access pricing and availability, not geographic redundancy.
  6. Which redundancy option combines zone-spread primary copies with asynchronous replication to a paired region?
    • A. GZRS
    • B. LRS
    • C. ZRS
    • D. Azure File Sync
    Answer

    Answer: A — GZRS.

    Reason: GZRS combines zonal primary redundancy with geo-replicated secondary LRS copies.

    • B — LRS uses one datacenter.
    • C — ZRS has no paired-region copy.
    • D — Azure File Sync synchronizes file servers and Azure Files.
  7. An administrator needs a repeatable command-line network transfer to Azure Blob Storage. Which tool is intended?
    • A. AzCopy
    • B. Azure Data Box
    • C. Azure Migrate
    • D. Availability set
    Answer

    Answer: A — AzCopy.

    Reason: AzCopy is a command-line copy and sync utility for Azure Storage.

    • B — Data Box moves data using a shipped physical appliance.
    • C — Azure Migrate handles broader workload discovery and migration.
    • D — Availability sets place VMs.
  8. A site has a very large dataset, but network bandwidth makes online transfer impractical. Which option is most suitable?
    • A. AzCopy only
    • B. Azure Data Box
    • C. Cool tier
    • D. Table Storage
    Answer

    Answer: B — Azure Data Box.

    Reason: Data Box uses a physical appliance for offline bulk transfer.

    • A — AzCopy depends on network connectivity.
    • C — Cool is a blob access tier.
    • D — Table Storage is a data service, not a transfer method.
  9. Which statement correctly separates Cool from Archive?
    • A. Cool is offline; Archive is online
    • B. Both are always online
    • C. Cool is online; Archive is offline and needs rehydration
    • D. Archive is a redundancy option
    Answer

    Answer: C — Cool is online; Archive is offline and needs rehydration.

    Reason: Cool supports immediate online access, while Archive trades access latency for lower storage cost.

    • A — The online/offline meanings are reversed.
    • B — Archive is not immediately readable.
    • D — Archive is an access tier, not redundancy.
  10. A migration planner needs discovery and assessment of servers and workloads, not merely a folder copy. Which service fits?
    • A. Azure Migrate
    • B. AzCopy
    • C. Azure Storage Explorer
    • D. Queue Storage
    Answer

    Answer: A — Azure Migrate.

    Reason: Azure Migrate is a broader discovery, assessment, and workload migration hub.

    • B — AzCopy copies or syncs storage data.
    • C — Storage Explorer is an interactive storage GUI.
    • D — Queue Storage stores asynchronous messages.
