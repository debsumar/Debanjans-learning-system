Describe monitoring tools in Azure

Separate recommendations, Azure incidents, and workload telemetry.

Domain 3Azure management and governance30–35%
In one minuteOfficial skillsTested trioAzure MonitorTelemetry flowComparison tablesMCQsQuick recall

In one minute

  • Advisor recommends improvements; Service Health reports Azure and resource service events; Monitor collects workload telemetry.
  • For one resource’s availability and health, use Resource Health; Service Health is the broader personalized service view.
  • Metrics are numeric time series; logs are queryable records and events, so match the signal to the question.
  • Log Analytics is the workspace and query experience for logs within Azure Monitor; it is not a separate telemetry product.
  • Alerts consume metric, log, or activity-log conditions; action groups route the response.

Common wrong turn

“Advisor tells you when Azure is broken.” — Advisor recommends improvements; Service Health reports Azure and resource service events.

Azure Monitor umbrella

Azure Monitor is the umbrella telemetry platform. It collects, correlates, queries, visualizes, and acts on signals from application → OS → resource → subscription → tenant.

Metrics
Numeric time series measured over time: CPU percentage, request count, latency, availability, or memory.
Logs
Queryable records and events: activity, diagnostics, application traces, errors, and structured telemetry.
Log Analytics workspace
Central workspace for collecting and querying log data with KQL (Kusto Query Language).
Azure Monitor alerts
Rules triggered by metric, log, or activity-log conditions; send through action groups to email, SMS, webhook, automation, and other actions, with severity.
Application Insights
Application performance monitoring (APM): request rates, response times, failures, dependency tracking, availability tests, and usage analytics.
Exam clueMetric alert = numeric threshold. Log alert = query result. Activity-log alert = management event such as a resource operation. Action group = response routing.

Signal layers

  • Application: requests, dependencies, exceptions, traces, usage.
  • OS and guest: process, performance, and operating-system events when configured.
  • Resource: platform metrics and diagnostic logs from Azure services.
  • Subscription and tenant: activity logs, governance events, and broader operational signals.

Telemetry flow

Sources feed Azure Monitor metrics and logs; specialized views and actions consume those signals.

  1. Sources emit signals

    Applications, operating systems, resources, subscriptions, and tenants emit telemetry.

  2. Azure Monitor collects

    Monitor collects, correlates, queries, visualizes, and acts on the signals.

  3. Metrics and logs store signals

    Metrics provide numeric time series; logs provide queryable records and events.

  4. Views, alerts, and actions consume signals

    Dashboards visualize, alerts evaluate conditions, and action groups route responses.

Log Analytics vs Azure Monitor
Log Analytics is the workspace and query experience for logs; Azure Monitor is the broader telemetry platform containing metrics, logs, alerts, dashboards, and integrations.
Application Insights vs Log Analytics
Application Insights is application-focused APM and instrumentation; its telemetry can be stored and queried through Azure Monitor and Log Analytics.
Service Health vs Resource Health
Service Health is the broader personalized view of Azure service issues, maintenance, and advisories; Resource Health focuses on availability and health of one resource.
Azure Status
Global public view of Azure service status; Service Health is personalized to your services, subscriptions, and relevant events.
Common wrong turn

“Service Health is only for your own resource failures.” — Resource Health focuses on one resource’s availability and health; Service Health is the broader personalized view of Azure service issues, maintenance, and advisories.

Common wrong turn

“Log Analytics and Azure Monitor are separate products.” — Log Analytics is the workspace and query experience for logs within the broader Azure Monitor telemetry platform.

Advisor and Service Health detail

Azure Advisor

Advisor provides personalised best-practice recommendations across reliability, security, performance, cost, and operational excellence. It reviews your resources and usage, then suggests actions such as right-sizing, improving resilience, or closing security gaps.

Azure Service Health

Service Health reports health of Azure itself and your resources: service issues, planned maintenance, and health advisories. It is personalized to relevant subscriptions and services. Compare its scope with Azure Status (global view) and Resource Health (one resource).

ConfuseMonitor answers “what telemetry says.” Advisor answers “how can I improve?” Service Health answers “is Azure or this resource affected by a service event?”

MCQs

  1. 1. Which Azure service is the umbrella for collecting and analysing metrics and logs?
    • A. Azure Monitor
    • B. Azure Advisor
    • C. Azure Service Health
    • D. Azure Status
    Answer

    Correct: A — Azure Monitor. Reason: Monitor collects, correlates, queries, visualizes, and acts on workload telemetry.

    • B — Advisor makes best-practice recommendations.
    • C — Service Health reports Azure and resource events.
    • D — Azure Status is a global public status view.
  2. 2. An engineer needs KQL queries over centralized log records. Which capability fits?
    • A. Log Analytics workspace
    • B. Azure Advisor
    • C. Resource Health
    • D. Action group
    Answer

    Correct: A — Log Analytics workspace. Reason: Log Analytics stores and queries log data with KQL within the Azure Monitor ecosystem.

    • B — Advisor suggests improvements, not KQL log queries.
    • C — Resource Health focuses on one resource’s availability.
    • D — Action groups route alert responses.
  3. 3. A developer wants request rates, dependency failures, response times, and availability tests for an application. Which tool is most focused on this?
    • A. Application Insights
    • B. Azure Policy
    • C. Service Health
    • D. Tags
    Answer

    Correct: A — Application Insights. Reason: Application Insights provides application performance monitoring and usage telemetry.

    • B — Policy governs resource configuration.
    • C — Service Health reports platform and resource events.
    • D — Tags provide metadata labels.
  4. 4. A metric crosses a threshold, and the team must route email and webhook responses. What Azure Monitor feature performs routing?
    • A. Action group
    • B. Log Analytics workspace
    • C. Azure Advisor
    • D. Resource Health
    Answer

    Correct: A — Action group. Reason: Alerts invoke action groups to route email, SMS, webhook, automation, and other responses.

    • B — Workspace stores and queries logs.
    • C — Advisor produces recommendations.
    • D — Resource Health reports one resource’s health state.
  5. 5. A customer asks whether a planned Azure maintenance event affects its subscription. Which service should answer?
    • A. Azure Service Health
    • B. Azure Monitor metric alert
    • C. Azure Advisor
    • D. Log Analytics
    Answer

    Correct: A — Azure Service Health. Reason: Service Health provides a personalized view of service issues, planned maintenance, and advisories.

    • B — A metric alert watches numeric workload telemetry.
    • C — Advisor recommends improvements.
    • D — Log Analytics queries collected logs.
  6. 6. A VM is unavailable, and the team needs the health state of that one resource rather than a broad Azure event view. Which distinction matters?
    • A. Resource Health focuses on one resource; Service Health is broader.
    • B. Service Health is only application APM; Resource Health is KQL.
    • C. Resource Health creates budgets; Service Health creates tags.
    • D. Both are identical names for Azure Monitor logs.
    Answer

    Correct: A — Resource Health focuses on one resource; Service Health is broader. Reason: Resource Health reports availability and health of a specific resource; Service Health covers relevant service events and advisories.

    • B — APM is Application Insights, and KQL is used with Log Analytics.
    • C — Neither health view creates budgets or tags.
    • D — They are distinct health views, not Monitor log names.
  7. 7. Which statement correctly compares Azure Monitor and Log Analytics?
    • A. Monitor is the broader platform; Log Analytics is workspace/query experience for logs.
    • B. Monitor is only a workspace; Log Analytics is all metrics and alerts.
    • C. They are unrelated services with no telemetry overlap.
    • D. Log Analytics is Azure’s global public status page.
    Answer

    Correct: A — Monitor is the broader platform; Log Analytics is workspace/query experience for logs. Reason: Monitor includes metrics, logs, alerts, dashboards, and integrations; Log Analytics specializes in logs and KQL.

    • B — The scopes are reversed.
    • C — Log Analytics is part of the Monitor ecosystem.
    • D — Azure Status is the public status page.
  8. 8. An alert rule should fire when a KQL query finds five failed deployments in a time window. Which alert type fits?
    • A. Log alert
    • B. Metric alert
    • C. Advisor recommendation
    • D. Service Health advisory
    Answer

    Correct: A — Log alert. Reason: Log alerts evaluate query results; metric alerts evaluate numeric time-series thresholds.

    • B — A metric alert does not directly represent a KQL query result.
    • C — Advisor recommendations are not alert rules.
    • D — Service Health advisories describe Azure events.
  9. 9. Which pairing is correct?
    • A. Advisor — “How can I improve my resources?”
    • B. Service Health — “Which KQL query stores logs?”
    • C. Application Insights — “Can an owner delete a locked group?”
    • D. Log Analytics — “Is Azure under planned maintenance?”
    Answer

    Correct: A — Advisor — “How can I improve my resources?” Reason: Advisor analyses configuration and usage to produce recommendations.

    • B — Service Health reports incidents, maintenance, and advisories.
    • C — Locks and authorization answer deletion protection, not Application Insights.
    • D — Log Analytics queries logs; Service Health reports maintenance.
  10. 10. A team wants a visual surface combining workload signals for operations review. Which Azure Monitor output fits?
    • A. Dashboard
    • B. Resource lock
    • C. Purview catalog
    • D. TCO Calculator
    Answer

    Correct: A — Dashboard. Reason: Dashboards visualize collected signals for review and operations.

    • B — A lock protects resource state.
    • C — Purview governs and catalogs data.
    • D — TCO Calculator compares on-premises and Azure cost.

Quick recall

Attempt each question before expanding it to check the answer.

What does Azure Advisor answer?

“How can I improve?” with recommendations across reliability, security, performance, cost, and operational excellence.

What does Service Health answer?

Whether Azure or your resources are affected by issues, maintenance, or advisories.

What does Azure Monitor do?

Collects and analyses metrics and logs across application, OS, resource, subscription, and tenant layers.

Metrics versus logs?

Metrics are numeric time series; logs are queryable records and events.

What is a Log Analytics workspace?

A workspace used to store and query log data with KQL.

What triggers an Azure Monitor alert?

Metric, log, or activity-log condition.

What routes alert actions?

Action groups to email, SMS, webhook, automation, and other actions.

What does Application Insights monitor?

Application performance: requests, response times, failures, dependencies, availability, and usage.

Azure Status versus Service Health?

Status is global; Service Health is personalized to relevant services and subscriptions.

Service Health versus Resource Health?

Service Health covers service events and advisories broadly; Resource Health focuses on one resource’s health.
