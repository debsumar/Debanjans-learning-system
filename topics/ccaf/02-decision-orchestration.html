Decision ownership and orchestration

Choose who decides next, constrain routes when code owns them, and adapt only when evidence changes required work.

Domain 1Agentic architecture and orchestrationWeight unverified
In one minuteSkills in scopeDecision ownershipConstrained routingFixed or adaptiveCoverage safeguardsMCQsQuick recall

In one minute

  • Use code-owned decisions when transitions and permitted routes must be fixed; tools alone do not make a workflow model-driven.
  • Use constrained classification output when code must route a known category set; unconstrained prose is a poor route contract.
  • Use model-driven decisions when a goal, runtime context, and available tools must determine the next action; keep stated boundaries around that discretion.
  • Use prompt chaining when work has a known fixed order; do not force an unchanged chain onto evidence-led investigation.
  • Review decomposition before delegation and coverage after aggregation; a correctly completed narrow task set can still omit needed work.

Skills in scope

This provisional mapping remains subject to the official guide when it is published.

  • Distinguish code-owned decision trees from model-driven decision ownership.
  • Design constrained classification output for code-driven routing.
  • Select prompt chaining for fixed work shape and adaptive decomposition for evidence-led work.
  • Select decomposition and coverage-review safeguards for broad work.

Who owns the next decision?

Code-driven decision-making uses fixed application logic, such as conditions or state transitions, to choose what happens next. In model-driven decision-making, the model selects next actions from the goal, runtime context, and available tools. Both can be useful; decision ownership is the discriminator.

QuestionCode-owned routeModel-owned next action
Decision ownerApplication code selects the next transition.Model selects the next action from stated context and tools.
OrderKnown conditions or a state machine set the order.Order can change at runtime as context changes.
Best fitLogic and states need constrained, predictable routing.Goal-directed work needs contextual tool or action selection.

Diagram: left route assigns the next action in code; right route gives the model a goal, context, and tools so it can select the next action.

ConfuseCode owns a fixed route when application rules choose the next decision. A model owns the next decision when runtime context and available tools inform its next action.
Common wrong turn

“Any workflow with several tools is model-driven.” — Tool availability does not decide ownership. A code-defined sequence can use tools while code still owns every transition.

Constrain classification before routing

When code owns routing, request a structured output category from a closed set, then map that category to a hard-coded handler. The transcript example used billing, technical, or general categories so code could act on one predictable result instead of interpreting free-form prose.

Constraint to choice: choose constrained classification when one known route must be selected from a known set. Choose model-owned action selection when the next tool or order must be inferred from the current goal and evidence rather than a fixed category map.

Common wrong turn

“A natural-language explanation is a safer route key than a constrained category.” — Explanation may be useful to a reader, but a route contract needs the known category that code can map to its handler.

Fixed chain or evidence-led decomposition?

Prompt chaining passes one call output into the next in a fixed sequence. It fits document processing, content transformation, and other work whose shape is known before the content arrives. Dynamic adaptive decomposition instead changes next work, agent choice, depth, or order after intermediate evidence changes what remains unknown.

DiscriminatorPrompt chainAdaptive decomposition
Work orderKnown and fixed before execution.Selected from intermediate findings.
Data flowEach output becomes input to the next known step.Evidence determines what task, depth, or angle follows.
FitFixed-shape transformations such as identify, propose, then apply fixes.Open-ended investigation where unknown depth or width affects next work.

An adaptive investigation treats each finding as a decision signal: ask what remains unknown, what evidence could change the conclusion, and which claim needs verification. Generate targeted work from those questions rather than running extra work at random.

ConfuseA prompt chain has a fixed order and passes output forward. Adaptive decomposition selects next work from evidence; it changes order, depth, or task only when the findings require it.

Protect broad work from narrow decomposition

A coordinator can delegate only the dimensions it creates. Isolated workers may execute their assigned scope correctly yet lack enough context to notice an unassigned topic. Review the breakdown against stated considerations before delegation, and review assembled coverage before a final answer.

  1. Define required considerations for the broad task.

    State the dimensions that coverage must address before converting the task into smaller assignments.

  2. Review proposed subtasks for missing or overlapping scope.

    Adjust the decomposition before delegation when a needed dimension has no owner or two scopes duplicate the same work.

  3. Delegate bounded work and aggregate returned evidence.

    Workers handle their assigned scopes; aggregation restores the overall view needed for coverage review.

  4. Check coverage before finalizing and fill identified gaps only.

    If coverage is insufficient, target the missing dimension rather than repeating all completed work. The transcript gives no universal quality threshold.

For evidence-led work, this pattern can become a bounded refinement loop: initial work, coverage evaluation, gap-only follow-up, then finalization only when the evaluation gate permits it. Observed score movement alone does not establish quality; representative data and human evaluation remain necessary.

MCQs

  1. A service must send billing, technical, or general requests to three fixed handlers. Which design owns the next decision?
    • A. Code-owned classification route
    • B. Model-selected tool sequence
    • C. Unbounded adaptive decomposition
    • D. Free-form explanation parsing
    Answer

    Answer: A — Code-owned classification route.

    Reason: The known categories map directly to fixed application handlers, so code selects the next transition.

    • B — Model-selected tool sequence fits when the model must choose actions from runtime context, not when handlers are fixed by category.
    • C — Adaptive decomposition fits evidence-led work with unknown next tasks, not a three-route classifier.
    • D — Free-form explanation parsing fits reader-facing explanation, not reliable selection among fixed handlers.
  2. What output contract best supports a code-driven customer-support router?
    • A. One category from billing, technical, or general
    • B. A detailed natural-language account of the issue
    • C. A request for every available tool
    • D. An unconstrained list of possible departments
    Answer

    Answer: A — One category from billing, technical, or general.

    Reason: A constrained output from the known set gives code a predictable route key.

    • B — A detailed account fits a human review or later analysis, not a closed routing contract.
    • C — Requesting tools fits model-directed runtime work, not classification output for code routing.
    • D — A list fits exploratory triage, not selection of one fixed handler.
  3. A document workflow always identifies defects, proposes fixes, then applies fixes. Which orchestration pattern fits?
    • A. Prompt chaining
    • B. Dynamic adaptive decomposition
    • C. Coverage-review refinement loop
    • D. Coverage-only finalization
    Answer

    Answer: A — Prompt chaining.

    Reason: The known fixed sequence passes each step output into the next step.

    • B — Dynamic adaptive decomposition fits when intermediate evidence must choose the next task or order, not this preknown sequence.
    • C — A coverage-review refinement loop fits broad delegated work when aggregation reveals a missing required dimension, not this fixed transformation pipeline.
    • D — Coverage-only finalization fits a final review gate, not the ordered transformation pipeline itself.
  4. An investigation finds a conflicting source that could change its conclusion. What should happen next?
    • A. Generate a targeted verification subtask
    • B. Continue the unchanged fixed plan
    • C. Repeat every completed task
    • D. Finalize because one source was collected
    Answer

    Answer: A — Generate a targeted verification subtask.

    Reason: Adaptive work uses a conclusion-changing finding to select the next evidence needed.

    • B — An unchanged fixed plan fits work whose order remains known regardless of evidence, not a finding that challenges the conclusion.
    • C — Repeating every task fits a full restart after invalidating all work, not gap-focused investigation.
    • D — Finalization fits after coverage and required verification permit it, not after an unresolved conflict appears.
  5. Three isolated workers complete sales, battery, and manufacturer research, but no task covers charging infrastructure. Which control was missed first?
    • A. Pre-delegation decomposition review
    • B. Tool-result correlation
    • C. A longer fixed prompt chain
    • D. A model-selected inventory tool
    Answer

    Answer: A — Pre-delegation decomposition review.

    Reason: Review against required considerations before assignment can reveal an unowned dimension.

    • B — Tool-result correlation fits matching execution output to a tool request, not assigning missing research scope.
    • C — A longer fixed prompt chain fits an expanded known transformation, not detection of an omitted broad-task dimension.
    • D — A model-selected inventory tool fits runtime inventory work, not coverage of research partitions.
  6. After workers return results, a coordinator finds one required dimension still lacks evidence. What is the appropriate refinement action?
    • A. Delegate only the identified gap, within a bound
    • B. Resubmit every worker
    • C. Ignore the gap because workers completed their tasks
    • D. Convert all results to free-form routing text
    Answer

    Answer: A — Delegate only the identified gap, within a bound.

    Reason: Coverage review feeds gap-only work back into a bounded refinement loop before finalization.

    • B — Repeating all workers fits a case where all prior work is invalidated, not a specific coverage gap.
    • C — Ignoring a gap fits only when a completion gate establishes that dimension is out of scope; completed assignments do not prove complete coverage.
    • D — Free-form routing text fits reader explanation, not resolving missing evidence.
  7. A team gives a model a goal, current context, and available tools but does not prescribe call order. Which statement is most accurate?
    • A. The model owns next-action selection at runtime
    • B. Code owns each fixed state transition
    • C. The workflow must be a prompt chain
    • D. Tool presence proves every route is safe
    Answer

    Answer: A — The model owns next-action selection at runtime.

    Reason: The model uses goal, context, and available tools to choose the sequence rather than receiving a code-defined order.

    • B — Code owns transitions when application conditions or a state machine specify each next step, not when order is left to the model.
    • C — Prompt chaining fits a known sequential pipeline, not an unspecified runtime-selected order.
    • D — Tool presence fits enabling possible actions, not proving routing safety or replacing stated boundaries.

Quick recall

Attempt each question before expanding it.

What distinguishes code-owned from model-owned decision-making?

Code-owned logic selects next transitions through conditions or state changes. Model-owned decision-making lets the model select next actions from goal, context, and available tools.

Why use one constrained category for a code-driven route?

A closed category gives code a predictable route key for its fixed handler. Free-form prose may explain an issue but is not the same route contract.

When does prompt chaining fit better than adaptive decomposition?

Use prompt chaining when the work shape and order are known before execution and each output feeds the next known step. Use adaptive decomposition when intermediate evidence determines what work follows.

What questions can convert a finding into adaptive next work?

Ask what remains unknown, what result could change the conclusion, and which claim needs verification. Use answers to create a targeted subtask.

Why can isolated workers not reliably detect every coverage gap?

They see assigned scope, not necessarily all required considerations. A coordinator must review decomposition and aggregate coverage at the broad-task level.

Where can coverage safeguards occur around delegation?

Review the proposed breakdown before delegation against required considerations, then review assembled coverage before finalizing. Fill identified gaps rather than automatically repeating all work.

Do available tools alone determine whether a workflow is model-driven?

No. Decision ownership determines it. Code can select tool calls through a fixed route, or a model can select actions at runtime; constrained classification supports the former when categories are known.
