Terms

Agentic loop
A repeated context, action, and verification cycle that continues toward a goal and can accept corrective feedback. Chapter context
Agent SDK
Transcript term for an SDK used in agent examples and contrasted with direct SDK patterns. Specific fields and capabilities require target language and version validation. Chapter context
Claude Code
Transcript-described CLI coding harness that gathers context, acts on a codebase, and verifies results. Product behavior remains version-sensitive. Chapter context
CLAUDE.md
Transcript-named project guidance file. The plans place procedures in skills rather than treating this file as the procedure itself. Chapter context
Stop reason
Structured response state used to determine whether a tool call is requested or a turn has completed. Use it with a bounded iteration guard rather than displayed text alone. Chapter context
Tool use
A requested tool call exposed in a response, including tool information and inputs for application handling. It is not the execution result. Chapter context
Tool result
Execution output returned to continue a tool-use conversation. It carries correlation to the requested tool call. Chapter context
Tool use ID
Identifier that maps a tool result to its specific requested tool call. Chapter context
Tool choice
Constraint selecting whether tool use is optional, requires any available tool, requires one named tool, or is disallowed. Mode behavior is transcript- and version-sensitive. Chapter context
Tool input schema
Contract describing tool arguments through properties, types, enums, nested objects, and required inputs. Chapter context
Code-driven decision-making
Application code owns what happens next through fixed logic such as conditions or state transitions. Chapter context
Model-driven decision-making
The model selects next actions from the stated goal, runtime context, and available tools. Chapter context
Coordinator
Central agent that routes work, controls context sharing, handles errors, observes execution, delegates, and aggregates results. Chapter context
Research partitioning
Division of selected research into needed, non-overlapping scopes with explicit rules and boundaries. Chapter context
Refinement loop
Coverage-review cycle that identifies gaps, performs gap-only work within a bounded attempt count, then finalizes. Chapter context
Observability
Evidence about execution such as structured traces, inputs, outputs, errors, IDs, latency, and coverage. Chapter context
Structured report
Explicit sub-agent result shape that can preserve success, empty, partial, or failure context for a coordinator. Chapter context
Structured output
Output constrained to an expected data shape for downstream handling. A requested shape is distinct from validated semantic quality. Chapter context
Few-shot prompting
Use of examples, including positive, negative, or scored examples, to constrain a target output. Examples do not guarantee truth. Chapter context
Prompt chaining
Fixed sequential pipeline in which one call output becomes input to the next call. It fits fixed-shape work. Chapter context
Dynamic adaptive decomposition
Evidence-led selection of next work, agents, depth, or order as intermediate results change what is needed. Chapter context
Handoff protocol
Structured package assembled before escalation so a recipient receives needed context without searching conversation history. Chapter context
MCP server
Configured and installed source whose tools can be discovered at connection time and exposed to the agent. Specific implementation claims require version validation. Chapter context
MCP resource
MCP capability intended for read-data access, contrasted with tool action intent. Do not infer immutability beyond the source plan. Chapter context
Agent definition
Pre-message blueprint for agent identity, routing description, prompt, allowed actions, and controls. SDK field names and availability require version validation. Chapter context
Allowed tools
Tool capability set permitted to an agent definition or workflow. Exact configuration fields are version-sensitive. Chapter context
Model selection
Choice of model option for task complexity, speed, long context, or plan and execution needs. Named options and behavior require current product verification. Chapter context
Session fork
New conversation branch from a prior point that preserves earlier history while later branch state remains isolated. Capability availability requires SDK and version verification. Chapter context
Context window
Available context capacity shared by material such as instructions, skills, messages, and summary headroom. Chapter context
Context compaction
Summarization intended to retain continuity while reducing conversation context use. Its exact command and behavior require version verification. Chapter context
Settings precedence
Ordering that determines which managed, user, project, or local setting applies when scopes overlap. Exact scope behavior requires version verification. Chapter context
Permission rule
Authorization rule that allows, asks about, or denies a tool or command under its matcher scope. Product-specific matching behavior requires verification. Chapter context
Sandbox
Execution boundary that constrains Bash-tool host access in the transcript-described flow. It is separate from permission authorization and varies by environment. Chapter context
Debug log
Diagnostic record used to inspect session detail, connections, tool state, and reproducible faults. Treat handling and sharing as version- and data-sensitive. Chapter context
Provenance
Claim origin and location evidence, such as source, document, page, or excerpt, retained with a finding. Chapter context
Finding
Structured evidence record that preserves a claim with attribution, location, excerpt, and confidence rather than raw text alone. Chapter context
Findings artifact
Persisted artifact holding exploration knowledge so later synthesis can use evidence without ingesting raw exploration context. Chapter context
Task manifest
Persisted task and recovery state used to reconcile interrupted or resumable work. Chapter context
Batch processing
Asynchronous submission and later retrieval pattern selected when cost matters more than immediate results. Transcript timing and API details require current verification. Chapter context
Progressive escalation
Support flow that attempts a supported resolution, requests clarification where needed, and escalates according to explicit triggers. Chapter context
