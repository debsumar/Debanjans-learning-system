Agent loops and tool-result control

Follow one requested tool turn through application work, correlated state, and a bounded exit.

Domain 1Agentic architecture and orchestrationWeight unverified
In one minuteSkills in scopeOrientationStop reasonsTool-use turnLoop exitWeather traceMCQsQuick recall

In one minute

  • When structured state requests tool use, dispatch matching application work; do not treat the request as the result.
  • Return each result with correlation to its requested call; a matching tool name does not identify a specific invocation.
  • Append the result to conversation state before asking for a follow-up; displaying a result does not continue the turn.
  • Exit on structured completion, not text that looks final; text can appear while more work remains.
  • Use a bounded iteration guard with structured completion; the cap limits runaway work but must not force needless turns after completion.

Skills in scope

This provisional mapping remains subject to the official guide when it is published.

  • Trace a tool-use turn from stop reason through dispatch, correlated result, and terminal response.
  • Select structured completion control using stop reason and bounded iteration rather than text parsing.
  • Distinguish tool request, tool result, displayed output, and conversation state.

Orientation

Common wrong turn

“A printed tool-use response completes the tool workflow.” — A tool request exposes work for application code. The application must run the requested work, return a correlated result, and obtain the next response.

Use the transcript material as a lab for observing a loop, not as proof of stable product or exam details. For a concrete run, inspect tool use metadata, implement the handler, then validate the resulting state with evidence such as returned messages and logs.

Stop reasons are control state

A stop reason is structured response state for deciding whether a turn requests a tool call or has completed. In the transcript example, a tool-use state means the client has work to handle; a terminal state means no further tool result is required for that turn.

Keep four things distinct: a tool request identifies intended work, a tool result carries execution output back, displayed output is reader-facing presentation, and conversation state is the message history used for continuation. One may be visible without proving another was updated.

ConfuseTool use is request/exposed call; tool result is correlated execution output. Structured completion is control state; displayed text can be misleading.

One ordered tool-use turn

A handler uses requested tool metadata and its input shape to select application code. It returns the output with the tool use ID for the specific invocation, then appends that result before requesting the next response.

  1. Receive a response whose structured state requests a tool.

    Locate the request and extract its tool name and input. A request is not execution output.

  2. Dispatch matching application code with the requested input.

    Use the declared tool metadata and input schema before judging behavior; inspect prerequisite or dependency errors first.

  3. Return a result correlated to that exact request.

    Include the request identifier so a shared tool name cannot attach output to the wrong invocation.

  4. Append the result to conversation state and receive a follow-up response.

    The next response may request another tool or provide structured completion.

Flow: request, dispatch, correlated result, append, then terminal response. This text remains the compact equivalent of the diagram.

ConfuseTool use is a request selected by tool name; tool result is correlated execution output. A tool use ID identifies one invocation.

Exit with structured evidence

Constraint to choice: if structured completion says the turn has ended, choose exit; if structured state requests tool work, choose handling and another response; if completion never arrives before the configured maximum, choose the iteration guard to stop runaway work.

Do not parse natural-language completion phrases or stop because any text appeared. A response can contain text while tool work remains, whereas structured state states the program control decision.

ConfuseEnd turn is structured completion; text is content and can appear before or after a turn ends. Choose the end turn state, not text, for loop control.
Common wrong turn

“Any returned text proves the agent loop is complete.” — Text is presentation content. Inspect structured completion and keep a bounded iteration guard for the control path.

Worked scenario: weather request

A user asks for weather in a city. The response requests a weather tool and supplies extracted city input. The application dispatches the matching handler, returns its result with the matching identifier, appends it to the conversation, and receives the terminal response.

When behavior is surprising, first inspect the requested name, input schema, response state, correlated identifier, follow-up message, and run evidence. This evidence-first sequence separates a handler or setup fault from a mistaken conclusion based only on rendered output.

Study the workflow by inspecting one example, implementing the same boundary, then validating observed behavior. This is a vendor-neutral learning method; implementation fields and exact response values remain version-sensitive.

MCQs

  1. A response requests a weather tool and includes city input. What should the client do next?
    • A. Display the request as the final answer
    • B. Dispatch the matching tool with the extracted input
    • C. End the loop because a response arrived
    • D. Return a correlated tool result before requesting the follow-up response
    Answer

    Answer: B — Dispatch the matching tool with the extracted input.

    Reason: A requested tool call identifies application work; the handler runs it before the conversation can continue.

    • A — Displaying a response is right when it is already a terminal answer, not when it requests tool work.
    • C — Ending is right when structured state indicates terminal completion, not merely because a response arrived.
    • D — Returning a correlated tool result is right after the matching handler has completed, not before dispatch.
  2. A client sends a tool result after a requested call. Which field best prevents attaching it to the wrong invocation?
    • A. The user display text
    • B. The tool use ID
    • C. The maximum iteration value
    • D. The terminal response text
    Answer

    Answer: B — The tool use ID.

    Reason: The identifier correlates a returned result with its specific requested invocation.

    • A — User display text is right for reader-facing presentation, not for identifying a tool invocation.
    • C — A maximum iteration value is right for bounding runaway work, not for correlating a result.
    • D — Terminal response text is right after completion, not for identifying the prior tool invocation.
  3. An agent loop receives friendly text, but its structured state still requests a tool. What is the reliable control action?
    • A. Exit because text looks complete
    • B. Ignore state and parse for a farewell phrase
    • C. Handle requested tool work and reevaluate structured state
    • D. Run exactly one more iteration regardless of state
    Answer

    Answer: C — Handle requested tool work and reevaluate structured state.

    Reason: Structured state controls whether work remains; text can appear before completion.

    • A — Exit is right when structured completion is present, not when text merely looks complete.
    • B — Phrase parsing is right only for text-analysis tasks, not for structured loop control.
    • D — One extra iteration is right only when a protocol explicitly requires it, not as a substitute for state.
  4. A dashboard shows a weather value, but the follow-up model response behaves as if it never received it. What likely boundary was missed?
    • A. The result was displayed but not appended to conversation state
    • B. The terminal response was shown twice
    • C. The user used a short prompt
    • D. The iteration cap was set too high
    Answer

    Answer: A — The result was displayed but not appended to conversation state.

    Reason: Presentation and conversation state are different; continuation needs the result in the message history.

    • B — Duplicate display matters when a user-facing rendering defect is under investigation, not when conversation state is absent.
    • C — Prompt length matters when input capacity or instruction quality is at issue, not for this missing handoff.
    • D — Iteration-cap size matters when bounding loop work, not when a result was never appended.
  5. A tool call appears to fail before its handler runs. What should an evidence-first investigation inspect first?
    • A. Tool metadata, input schema, and prerequisite errors
    • B. The structured response state and requested tool block
    • C. A larger iteration cap
    • D. The correlated tool result from a completed handler
    Answer

    Answer: A — Tool metadata, input schema, and prerequisite errors.

    Reason: These establish what was requested and whether setup blocked execution before behavior is judged.

    • B — Structured response state and a tool block are right when confirming what the model requested, but metadata, schema, and prerequisites diagnose pre-dispatch failure first.
    • C — A larger iteration cap is right when runaway work needs a bound, not when malformed input or setup blocks dispatch.
    • D — A correlated tool result is right when a handler completed and its output is under investigation, not before the handler runs.
  6. A course transcript makes a claim about certification format. How should a study page handle that claim before an official guide confirms it?
    • A. Present it as fixed exam fact
    • B. Cite it as a transcript observation with its source
    • C. Mark it unverified and seek official confirmation
    • D. Treat it as a provisional study hypothesis pending guide comparison
    Answer

    Answer: C — Mark it unverified and seek official confirmation.

    Reason: Transcript-reported format and score constraints are not durable exam facts without official confirmation.

    • A — Presenting it as fixed fact is right only after an authoritative guide confirms it.
    • B — Citing a transcript observation is right when documenting its provenance, but it does not confirm certification status.
    • D — A provisional study hypothesis is right for internal exploration, but the page must visibly mark the claim unverified and seek official confirmation.
  7. A learner can describe a tool loop but has never observed one run. Which next activity follows the stated lab-first method?
    • A. Memorize only the displayed answer
    • B. Inspect an example, implement it, then validate behavior
    • C. Increase the iteration limit without testing
    • D. Implement the boundary before inspecting any example
    Answer

    Answer: B — Inspect an example, implement it, then validate behavior.

    Reason: The lab-first loop connects a concrete example to implementation and observed evidence.

    • A — Memorization is right for later retrieval practice, not for validating a workflow never observed.
    • C — A larger iteration limit is right when bounded loop capacity needs adjustment, not as implementation evidence.
    • D — Implementing first fits work whose requirements and behavior are already established and the goal is independent execution, but lab-first learning starts by inspecting an example before implementation.
  8. A loop must stop promptly when complete yet limit runaway tool work. Which control design fits?
    • A. Parse final-sounding prose only
    • B. Use a fixed number of turns with no early exit
    • C. Check structured completion and enforce a maximum iteration cap
    • D. Stop after the first tool request
    Answer

    Answer: C — Check structured completion and enforce a maximum iteration cap.

    Reason: Structured state permits timely normal exit; the cap bounds runaway work.

    • A — Parsing prose is right for interpreting content, not for reliable loop completion control.
    • B — Fixed turns are right only for a protocol with an exact required count, not for early completion plus runaway protection.
    • D — Stopping after one request is right only when no result or follow-up is required, unlike a tool-use turn.

Quick recall

Attempt each question before expanding it.

Trace a requested tool turn to its terminal response.

Read structured request state, extract name and input, dispatch matching code, return a correlated result, append it to conversation state, then inspect the follow-up for terminal completion or another request.

What two controls should an agent loop combine for normal exit and runaway protection?

Check structured completion state for normal exit and use a maximum iteration guard to bound runaway work.

How do tool request, tool result, displayed output, and conversation state differ?

Request asks application code for work; result returns execution output; displayed output is presentation; conversation state is the messages used to continue the turn.

What should you inspect before concluding a requested tool failed?

Inspect tool name and metadata, input schema, response state, prerequisite or dependency errors, correlated identifier, follow-up response, and run evidence.

A transcript reports a score rule but no official guide exists. How does a provisional study note differ from a confirmed certification rule?

Keep the transcript claim labeled unverified and source-bound; only an official guide can support presenting the score rule as confirmed certification guidance.

A learner can restate a loop but has not observed one. Which next action distinguishes lab-first learning from rereading?

Inspect a working example, implement the boundary yourself, then validate observed behavior with returned state or other execution evidence; rereading alone does not provide that run evidence.

Why is a correlation identifier needed with a tool result?

It maps output to the exact requested invocation when tool names alone do not distinguish the request.

Why should completion not depend on text that looks final?

Text can appear while more tool work remains. Structured completion state is the reliable control signal; the iteration cap separately limits runaway work.
