Tools, MCP, and structured output

Choose minimal capability, constrain arguments, and distinguish read intent from action intent.

Domain 2Tool design and MCP integrationWeight unverified
In one minuteSkills in scopeTool selectionSchemasTool choiceMCPMCQsQuick recall

In one minute

  • Choose the least-scope capability that performs the task; a broad shell can work, but is not the default for a named read, search, or edit operation.
  • Use a schema to constrain argument shape with types, enums, nested objects, and required fields; valid shape does not prove semantic correctness.
  • Choose auto when tool use is optional, any when one listed tool is required, named tool when one specified tool is required, and none when tool use is prohibited.
  • Handle named-tool loops explicitly; forcing a named tool can prevent a normal end turn in the transcript pattern.
  • Use MCP resources for read-data intent and MCP tools for action intent; neither label alone proves an implementation-enforced immutability boundary.

Skills in scope

This provisional mapping remains subject to the official guide when it is published.

  • Choose least-scope tool capability for read, search, edit, shell, or delegated work.
  • Interpret JSON Schema types, enums, nested structures, and required fields for tool arguments.
  • Select auto, any, named tool, or none while controlling named-tool loop risk.
  • Distinguish MCP discovery, resources, and tools without overstating resource immutability.

Choose least-scope tool capability

A tool is callable external code with a name, expected input, and output. Select the narrowest allowed tools capability that directly matches the work. Named operations make intent inspectable and reduce unnecessary authority.

NeedLeast-scope choiceWhy it fitsBoundary
Load one known fileReadReturns that file's contents.Use search first if the file path is unknown.
Find matching file pathsGlobMatches names and path patterns.It does not search text inside files.
Find text occurrencesGrepSearches file content by pattern.It does not replace the need to read surrounding context.
Change a known fileEditTargets a file modification.Verify the changed result after the edit.
Run a command or testShellProvides general command execution.It is broader than named file operations and needs added authorization attention.
Delegate a bounded subtaskAgentRuns a scoped delegated task.State task, context, and tool boundary; delegation does not replace task design.

For a failing test example, read the test for context, edit the target for action, then run a test command for verification. This is an illustrative sequence, not a claim that every repair has the same order.

Common wrong turn

“Shell is the best default because it can do everything.” — Shell capability is broader. Choose read, glob, grep, or edit when a named operation meets the requirement with less scope.

Schema constrains argument shape

A tool input schema describes the arguments expected by a tool. It can state named properties, primitive types, an enum of allowed values, nested objects, arrays of items, and required properties. The contract guides generation and lets the receiving tool validate shape.

Schema constructQuestion it answersExample tool-argument use
String, integer, number, booleanWhat basic value type belongs here?A city name, retry count, threshold, or include-details flag.
EnumWhich fixed values are allowed?Limit unit to Celsius or Fahrenheit.
RequiredWhich property must be present?Require a location before a weather lookup.
ObjectWhich named values form one nested record?Group address fields under one destination object.
Array and itemsWhich repeated values are accepted?Accept a list of identifiers, each constrained by an item schema.

Schema validation can reject absent required fields, unsupported enum values, or the wrong structural type. It cannot establish that a supplied city is the intended city, that a triage classification is correct, or that a tool result is safe to act on. Those are semantic and business-rule questions.

Common wrong turn

“A valid structured argument proves the requested action is correct.” — Schema validation checks format constraints. Semantic correctness still needs task rules, evidence, or review.

In the transcript pattern, named tool requires the particular tool name. If each request in a response loop keeps forcing that tool, append a result only with an explicit break or termination strategy. Otherwise the next request can again require the named tool instead of allowing end turn.

Confuseany requires any one listed tool; named tool requires one specified named tool. Both constrain use, but any leaves selection among listed tools while named tool fixes the required tool.
Common wrong turn

“A named tool guarantees one call and then completion.” — In the shown loop pattern, a named-tool requirement can continue on each request. Add explicit loop control or choose a mode that permits normal completion.

MCP discovery, resource, and tool intent

A configured MCP server can expose capabilities when a connection is established. The transcript describes tools from configured servers being discovered into a flat agent-visible list; that list does not preserve a usable source-server identity for selection. Treat code examples and field names as version-specific until tested in the target implementation. An MCP resource represents read-data intent; a tool represents action intent.

Diagram: configured MCP servers contribute discovered capabilities to one flat list. A resource represents read-data intent; a tool represents action intent.

ConfuseMCP resource means read-data intent; MCP tool means action intent. Resource does not prove immutability, and tool does not identify a resource. Use the intent and operation, not an unsupported enforcement claim.

For a narrow tool-use demonstration, avoid adding an MCP layer solely because tools exist. A direct function or bounded endpoint may be the simpler architecture. Validate uncertain SDK or documentation claims against the target version before relying on generated code.

MCQs

  1. A task needs the contents of one known file. Which capability is least scope?
    • A. Read
    • B. Glob
    • C. Grep
    • D. Shell
    Answer

    Answer: A — Read.

    Reason: Read directly loads a known file's contents without broader search or command authority.

    • B — Glob fits discovering file paths by a name pattern, not loading one known file.
    • C — Grep fits finding matching text across file contents, not reading one identified file.
    • D — Shell fits a command or test that needs general execution, but is broader than this task.
  2. A task must locate all files named like a calculator module before inspecting them. Which capability fits?
    • A. Read
    • B. Glob
    • C. Edit
    • D. Agent
    Answer

    Answer: B — Glob.

    Reason: Glob discovers paths that match a filename pattern.

    • A — Read fits loading a file once its path is known, not discovering matching paths.
    • C — Edit fits changing a known file, not locating candidate files.
    • D — Agent fits delegating a bounded task, not the least-scope primitive path search.
  3. A weather tool accepts only Celsius or Fahrenheit for its unit. Which schema construct constrains that value set?
    • A. Required
    • B. Enum
    • C. Array items
    • D. Nested object
    Answer

    Answer: B — Enum.

    Reason: An enum restricts a property to an explicit set of allowed values.

    • A — Required fits making a property present, but does not restrict which value it contains.
    • C — Array items fit constraining repeated values in a list, not one fixed-value property.
    • D — A nested object fits grouping named properties, not limiting a scalar to two values.
  4. A delivery tool must receive destination.city and destination.postcode together. Which schema structure best represents that group?
    • A. A nested object
    • B. An enum
    • C. A boolean
    • D. An unrelated flat string
    Answer

    Answer: A — A nested object.

    Reason: A nested object groups related named properties into one destination record.

    • B — An enum fits a fixed allowed set, not a record with city and postcode fields.
    • C — A boolean fits a true-or-false flag, not structured address data.
    • D — A flat string fits one unstructured value, not separately constrained destination fields.
  5. A triage record satisfies every required field and enum. What remains unproven?
    • A. Its JSON shape
    • B. Its semantic classification correctness
    • C. Whether required fields are present
    • D. Whether enum values are allowed
    Answer

    Answer: B — Its semantic classification correctness.

    Reason: Schema compliance constrains structure, not whether a categorization is factually or operationally correct.

    • A — JSON shape is what schema validation can establish for a structurally compliant record.
    • C — Required-field presence is exactly what the required constraint checks.
    • D — Allowed enum values are exactly what an enum constraint checks.
  6. An application may use a lookup tool if useful, but may also answer without it. Which tool-choice mode fits?
    • A. auto
    • B. any
    • C. Named tool
    • D. none
    Answer

    Answer: A — auto.

    Reason: Auto permits a tool decision rather than requiring or prohibiting a call.

    • B — Any fits when some supplied tool must be called, which the optional lookup does not require.
    • C — Named tool fits when one specific tool must be called, stronger than this optional condition.
    • D — None fits when all tool use is prohibited, opposite to permitting an optional lookup.
  7. A workflow must call one tool from a provided list, but any suitable member is acceptable. Which mode fits?
    • A. auto
    • B. any
    • C. Named tool
    • D. none
    Answer

    Answer: B — any.

    Reason: Any requires a call while allowing selection among supplied tools.

    • A — Auto fits an optional call, not a requirement to call one supplied tool.
    • C — Named tool fits a requirement for one particular tool, not selection among several.
    • D — None fits prohibition of tools, not required use.
  8. A response loop repeatedly calls submit_triage after named-tool selection. What control should the handler add?
    • A. An explicit break or termination strategy
    • B. More unrelated tools
    • C. A looser enum
    • D. A display-only final message
    Answer

    Answer: A — An explicit break or termination strategy.

    Reason: A forced named tool can keep being required on subsequent requests unless loop control permits exit.

    • B — More tools fit broader task capability, not stopping a loop forced to one named tool.
    • C — A looser enum fits accepting more argument values, not response-loop termination.
    • D — A display message fits presentation, not control of the next required tool request.
  9. A user asks to list existing todos without changing them. Which MCP capability intent best fits?
    • A. MCP resource
    • B. MCP tool
    • C. Named tool choice
    • D. Shell by default
    Answer

    Answer: A — MCP resource.

    Reason: The transcript distinction uses resources for read-data intent, such as listing todos.

    • B — An MCP tool fits an action such as creating, updating, or deleting a todo.
    • C — Named tool choice controls whether a particular tool is required, not resource-versus-action intent.
    • D — Shell fits general command execution, not the stated MCP read-data capability choice.
  10. Which statement is defensible about MCP resources in this chapter's source boundary?
    • A. A resource is technically incapable of mutation
    • B. A resource expresses read-data intent, but does not prove enforced immutability
    • C. A resource always bypasses server logic
    • D. A tool cannot read data
    Answer

    Answer: B — A resource expresses read-data intent, but does not prove enforced immutability.

    Reason: The transcript uses a resource/tool design distinction while explicitly avoiding a stronger enforcement claim.

    • A — Technical impossibility would require an enforcement guarantee not supplied by the source.
    • C — Direct-read intent can still involve callable server logic; it does not prove bypass of implementation logic.
    • D — A tool can read data when that read is part of an action-oriented tool design; the distinction is intent.

Quick recall

Attempt each question before expanding it.

What is the least-scope tool for loading one known file?

Read. Use glob when the path is unknown and a filename pattern must locate candidates first.

How do glob, grep, edit, and shell differ?

Glob finds paths by pattern; grep searches file content; edit changes a known file; shell executes general commands and therefore has broader scope.

Why is least-scope selection useful?

It makes intended work and authority boundaries clearer. Choose a broad capability only when narrower named operations cannot meet the task.

What does enum constrain in a tool input schema?

Enum limits a property to an explicit allowed value set, such as Celsius or Fahrenheit.

What does required express, and what does it not prove?

Required says a property must be present. It does not prove that the supplied value is semantically correct or appropriate.

When do arrays and nested objects help a schema?

Arrays constrain repeated items; nested objects group related named properties into one structured record.

Which modes map to optional, required-any, required-named, and prohibited tool use?

Use auto for optional, any for one supplied tool, named tool for one specified tool, and none to prohibit tool use.

Why can named tool choice create a loop risk?

If every response request forces the same named tool, appending a result can lead to another forced request. Add an explicit break or another termination strategy.

How does the transcript describe MCP discovery?

Configured and installed MCP servers expose discovered capabilities at connection time. The agent sees a flat tool list rather than useful source-server identity.

What is the resource-versus-tool discriminator, including its boundary?

A resource has read-data intent and a tool has action intent. Do not infer that the resource label alone enforces immutability or prevents callable implementation logic.
