Discrimination drill

Attempt each distinction before opening its answer. Links go to the chapter callout that owns it.

tool_use vs tool_result: which is the request or exposed call, and which is correlated execution output?

tool_use is the request or exposed call; tool_result is correlated execution output returned after handling it. Open tool-turn callout.

end_turn vs displayed text: which is structured completion, and which can be misleading content?

end_turn is structured completion evidence; displayed text can appear while tool work remains and is not sufficient exit evidence. Open loop-exit callout.

Code-driven vs model-driven decision-making: which party owns the next decision?

Code-driven logic owns fixed transitions and routes; model-driven work lets the model select the next action from goal, context, and available tools. Open decision-owner callout.

Prompt chain vs adaptive decomposition: which has fixed order, and which selects work from evidence?

A prompt chain uses a known fixed sequence; adaptive decomposition changes next work, agent, depth, or order when evidence changes what is needed. Open fixed-vs-adaptive callout.

Coordinator vs sub-agent: which orchestrates, routes, and aggregates, and which performs bounded work?

The coordinator owns decomposition, routing, context decisions, aggregation, and cross-work concerns; a sub-agent executes its assigned bounded work and returns a result. Open hub-spoke callout.

Parallel vs sequential delegation: is independence or a prior-result dependency the discriminator?

Use parallel delegation for independent subtasks; use sequential delegation when a later worker needs an earlier result. Open delegation callout.

Partitioning vs selection: which divides selected work, and which decides whether work is needed?

Selection decides whether a dimension needs work; partitioning divides already selected work into non-overlapping scopes. Open partitioning callout.

Validation retry vs task recovery: which corrects an artifact, and which resumes interrupted durable work?

A validation retry feeds a specific artifact failure into bounded remediation; task recovery reconciles persisted state and resumes interrupted durable work. Open recovery callout.

Schema validity vs semantic quality: is the discriminator format contract or factual and business correctness?

Schema or syntax validity checks required shape; semantic and business validation check whether values are correct, coherent, and policy-satisfying. Open validation callout.

Self-review vs independent review: which retains generator history, and which uses fresh context?

Self-review retains the generator context and its bias risk; independent review uses a separate fresh context to inspect the artifact. Open review callout.

MCP resource vs MCP tool: which has read-data intent, and which has action intent?

An MCP resource has read-data intent; an MCP tool has action intent. Read intent does not assert that an implementation makes mutation impossible. Open MCP callout.

any vs named tool: may any listed tool satisfy the constraint, or must one named tool be used?

any requires one of the listed tools; a named-tool constraint requires that specific named tool and can increase loop risk if its result does not resolve the task. Open tool-choice callout.

Provenance vs confidence: which records claim origin and location, and which is a certainty signal?

Provenance records source, location, and supporting evidence; confidence is an assessed certainty signal and cannot replace origin. Open findings callout.

Findings vs manifest: which preserves evidence knowledge, and which preserves task and recovery state?

Findings preserve evidence knowledge for synthesis; a task manifest preserves task identity and recovery state for orchestration. Open durable-artifacts callout.

Claude Code workflow vs Agent SDK application: which is a CLI coding harness, and which is a program integration boundary?

A Claude Code workflow is a coding-harness loop for context, action, and verification; an Agent SDK application is program-owned integration. Shared terms do not erase that ownership boundary. Open setup-boundaries callout.

Fork vs resume vs rewind: which creates a new branch, continues, or changes the current history point?

Fork creates an isolated branch from a shared baseline; resume continues a chosen conversation; rewind changes the current conversation back toward an earlier point. Open session-lifecycle callout.

Compact vs clear: which preserves summarized continuity, and which removes conversation history?

Compact reduces context while retaining summarized continuity; clear removes conversation history when it must not influence the next task. Open context callout.

Project vs local settings: which is shared repository convention, and which is untracked local preference?

Project settings fit repository conventions intended for collaborators through version control; local settings fit an individual untracked preference. Open settings-scopes callout.

Permission rule vs sandbox: which authorizes an action, and which constrains Bash execution environment?

A permission rule authorizes, asks about, or denies an action; a sandbox constrains Bash execution if Bash runs. Neither alone is an all-tool security guarantee. Open sandbox callout.

Do-not-ask vs bypass: which auto-denies unless approved, and which skips prompts?

Do-not-ask is the restrictive posture that auto-denies unless explicitly approved; bypass skips prompts and therefore needs exceptional risk controls. Exact product mode names remain version-sensitive. Open modes callout.

Completion text vs durable completion: which is reported success, and which is a verified artifact?

Completion text only reports what a layer said; durable completion requires inspecting the expected persisted artifact, relevant logs, or other evidence at the boundary. Open run-evidence callout.

Agent description vs skill procedure: which is routing or invocation language, and which is executable steps?

An agent description says when the agent fits and supports routing; a skill procedure contains repeatable executable steps. A routing label is not an operating procedure. Open agent-definition callout.

Batch ID vs custom_id: which identifies batch retrieval, and which correlates a request with its result?

A batch ID identifies the submitted batch for later status or retrieval; custom_id correlates each independent request with its result. Open batch callout.

Explicit human request vs frustration: which triggers immediate escalation, and which first calls for a supported solution attempt?

An explicit human request is an immediate escalation trigger. Frustration alone does not make escalation automatic; attempt a supported resolution first unless another decisive trigger applies. Open escalation callout.

Cross-chapter scenarios

Choose first, then reveal answer and rationale. Each scenario crosses chapter boundaries.

A tool loop shows friendly text after a response, but structured state requests a tool. What must the handler do before it can exit, and how should it validate the tool arguments?

Do not exit from displayed text. Dispatch the requested tool, return a correlated result, append it, then inspect the next structured state; validate arguments against the tool input schema before execution. Loop exit and tool schemas.

A support service has three fixed categories, but an investigation may need new evidence-led subtasks. Which decision owner and orchestration shape fit each part?

Use constrained code-owned classification for the fixed categories. Use model-driven, evidence-led adaptive decomposition only where new findings determine the next investigation work. Routing and adaptive decomposition; preserve bounded handoff when work reaches specialists in coordinator design.

Three research axes are independent, but a final writer needs all results and one required dimension may still be absent. How should the coordinator delegate and finish?

Delegate the independent axes in parallel with explicit scopes and a merge rule. Aggregate reports, evaluate coverage, then delegate only any identified gap within a bound before finalization. Delegation and bounded refinement.

An interrupted explorer left useful findings and task state marked running. Should the system rerun every validation step or recover work, and what records make that possible?

Recover the durable task: scan and reconcile recorded state, preserve useful findings, then resume required work. A task manifest holds recovery state, while findings hold evidence knowledge; validation retry instead corrects a failed artifact. Recovery and durable artifacts.

A generated extraction is schema-valid but may be wrong for one document type. What validation and review path fits before an automated action?

Schema validity is only the shape gate. Check semantic and business correctness, segment evidence by field and document type, and route uncertain fields to independent or human review before action. Validation and independent review; narrow action authority in tool selection.

An agent may read a resource for context but must use one specific action tool to make a required update. What distinctions control capability and tool choice?

Use an MCP resource for read-data intent and a tool for action intent. If one exact action tool is required, use the named-tool constraint rather than any; verify target implementation syntax and behavior. MCP intent and tool choice.

A synthesizer receives a confident claim with no source location while an interrupted task needs restart. What must it preserve for the claim and for recovery?

Require provenance: source, usable location, and supporting excerpt alongside confidence. Preserve task recovery state separately in a manifest so restart can reconcile work without treating confidence as evidence. Findings and durable artifacts; apply restart in recovery.

A local coding harness command succeeds, but a planned application integration still lacks evidence. What conclusion is justified and what loop remains?

The smoke test proves only installation, authentication, and a minimal local action. It does not prove application credentials, permissions, asynchronous control flow, data handling, or tool behavior; gather context, take bounded action, and verify at the application boundary. Setup boundary and coding loop.

A team needs an independent branch from a shared investigation, then wants shorter continuity without deleting prior reasoning. Which session actions fit, and what must be checked first?

Fork the session for an isolated branch from the shared baseline. Inspect active-session context, then compact if summarized continuity is needed; do not clear history. Confirm command and behavior details against the target version. Session lifecycle and context decisions.

A repository-wide convention should be shared, while a developer has a personal preference. A command is dangerous outside a narrow path. Which setting scopes and safety controls fit?

Put the shared convention in project scope and the personal preference in local scope. Use a narrowly tested permission matcher and appropriate approval posture; a sandbox is execution containment, not authorization. Settings scopes and rule resolution.

An automation run says completed, but its expected report is absent and logs show unexpected tool state. What should happen before a retry or trust decision?

Capture reproducible status and diagnostic evidence, inspect the expected persisted artifact directly, and identify the failed boundary. Completion wording alone is not durable success; retry only after the diagnosis supports a bounded next action. Status and debug, run evidence, and bounded refinement.

An evidence-review agent is never selected, and its generated configuration uses a field undocumented in the target SDK. What should the team inspect and verify?

Inspect the agent description and routing language first, then verify target language, target version, current documentation, and a focused behavior test before relying on the field. Keep the description distinct from a skill procedure. Agent definition and SDK parity; compare workflow roles in harness roles.

A cost-sensitive backlog contains independent requests, but a frustrated live user asks for a person after repeated failed attempts. Which work goes to batch, and which routing action fits?

Submit only independent work whose result can wait to asynchronous batch processing, retaining correlation identifiers. Escalate the live case because an explicit human request and repeated failed attempts are decisive triggers; frustration alone would first call for a supported solution attempt. Batch processing and escalation.
