Coordinator and multi-agent design

Route bounded work through one accountable hub, then combine results without assuming shared context.

Domain 1Agentic architecture and orchestrationWeight unverified
In one minuteSkills in scopeHub and spokeDelegation modePartitioningContext handoffMCQsQuick recall

In one minute

  • Keep routing, context sharing, error handling, and result aggregation with the coordinator; a spoke executes its assigned bounded task.
  • Use one agent for a simple factual task; use sequential delegation only when later work needs an earlier result.
  • Use parallel delegation only for independent subtasks; concurrent calls do not remove the need to combine or check outputs.
  • Partition selected work into non-overlapping scopes with include and exclude boundaries; different agent names alone do not prevent overlap.
  • Hand off required task context explicitly; isolated sub-agents do not inherit coordinator context or every tool by default.

Skills in scope

This provisional mapping remains subject to the official guide when it is published.

  • Define coordinator responsibilities and hub-and-spoke communication boundaries.
  • Choose single, sequential, or parallel delegation from dependency and independence.
  • Design non-overlapping partitions with one routing owner and explicit scope boundaries.
  • Apply explicit context handoff and isolated sub-agent/tool boundaries.

Coordinator-owned hub and spoke

A coordinator receives the task, decomposes it, chooses bounded subagent work, passes needed context, receives results, and aggregates a response. The transcript pattern places routing, shared-context decisions, error handling, and observability at this hub rather than distributing them across peers.

A spoke is an assigned worker, not a peer router. It can return a result to the coordinator, but direct spoke-to-spoke communication is outside this hub-and-spoke boundary. That central path gives one accountable place to inspect traffic, resolve conflicts, and decide what happens next.

ConfuseCoordinator means the hub that orchestrates, routes, shares context, and aggregates. A spoke is a bounded execution worker. A spoke does not replace the coordinator or directly coordinate with another spoke.
Common wrong turn

“Subagents should pass context directly to each other for speed.” — In this pattern, the coordinator owns context routing and result aggregation. A direct peer path removes the central control boundary.

Diagram: task context travels from coordinator to isolated spokes; each result returns to the coordinator for aggregation. The diagram does not show peer-to-peer spoke links.

Choose delegation from dependency

Constraint to choice: use one agent when one bounded answer is enough. Use sequential delegation when a later worker needs an earlier result. Use parallel delegation when subtasks are independent and the coordinator can later combine their outputs.

ConfuseParallel means independent work can proceed without a prior result. Sequential means a later task depends on an earlier result. Parallel is not a synonym for faster when dependency remains.

Parallel fan-out is a coordinator decision, not proof that every spawned agent has concurrent scheduling or visible internal progress. Keep the task dependency and permission boundary explicit, then inspect and combine returned work.

Common wrong turn

“Every specialist should run for completeness.” — Invoke a specialist when it answers a relevant unanswered question; a mechanical pipeline can add cost and irrelevant output.

Partition selected work without overlap

Selection asks whether a dimension needs work. Research partitioning divides work already selected into distinct scopes. A useful partition names its worker, scope, and rules, including what it includes and excludes.

Common wrong turn

“Different agent names make the research non-overlapping.” — Scope and include/exclude boundaries prevent overlap. Names alone do not state what each worker must avoid.

Explicit context handoff

Subagents operate with isolated context and assigned tools. Before delegation, the coordinator must supply the task, relevant evidence or constraints, expected result shape, and only the tool capability needed for that task. Do not assume a worker sees parent conversation or can infer an omitted boundary.

  1. Define the bounded task and the evidence needed to complete it.

    State what question the subagent answers and what remains outside its scope.

  2. Pass task-specific context, criteria, and least-scope tools.

    Give the worker enough information to act without handing it unrelated context or every available tool.

  3. Receive a result through the coordinator.

    Keep the result associated with its task so the coordinator can inspect coverage and conflicts.

  4. Aggregate or route the next dependent step.

    The coordinator combines independent results or forwards the needed prior result to a later worker.

A structured handoff prevents a recipient from searching prior conversation history for basic task facts. It is a context package for the next bounded action, not an assumption of shared memory.

MCQs

  1. A research worker and a review worker need to exchange a finding. Which path preserves hub-and-spoke control?
    • A. Research worker sends it directly to review worker
    • B. Coordinator receives it and passes needed context to review worker
    • C. Each worker broadcasts it to all workers
    • D. Review worker rereads the entire parent conversation
    Answer

    Answer: B — Coordinator receives it and passes needed context to review worker.

    Reason: The coordinator owns routing and explicit context handoff between isolated spokes.

    • A — Direct delivery fits a peer-messaging architecture, not this coordinator-controlled hub-and-spoke boundary.
    • C — Broadcast can fit a deliberately shared event system, not bounded coordinator routing for this stem.
    • D — Rereading history fits a shared-context workflow, not an isolated worker requiring explicit handoff.
  2. Which responsibility belongs to the coordinator rather than a bounded spoke?
    • A. Execute one assigned evidence lookup
    • B. Choose which subtasks to invoke and aggregate their results
    • C. Return an assigned report within its scope
    • D. Use only its assigned tool capability
    Answer

    Answer: B — Choose which subtasks to invoke and aggregate their results.

    Reason: Routing, decomposition, and aggregation are coordinator responsibilities.

    • A — An evidence lookup fits a spoke when the coordinator has assigned that bounded task.
    • C — A scoped report fits a spoke after it completes delegated work.
    • D — Least-scope tool use fits a spoke boundary, not coordinator-only orchestration.
  3. A request asks one straightforward factual question with no separate research dimensions. Which delegation mode fits first?
    • A. One agent
    • B. Sequential delegation
    • C. Parallel delegation
    • D. Three identical research partitions
    Answer

    Answer: A — One agent.

    Reason: A simple bounded factual task does not need coordination overhead.

    • B — Sequential delegation fits when a later task needs an earlier result, absent in this stem.
    • C — Parallel delegation fits independent subtasks, which this single-question request lacks.
    • D — Multiple partitions fit broad work needing distinct scopes, not one simple fact.
  4. A writer can begin only after a researcher returns verified facts. Which mode fits?
    • A. One agent with no handoff
    • B. Parallel delegation
    • C. Sequential delegation
    • D. Broadcast all tasks without order
    Answer

    Answer: C — Sequential delegation.

    Reason: The writer depends on the research output, so the coordinator must pass that result forward.

    • A — One agent fits when one bounded worker can complete the whole request without a required specialist handoff.
    • B — Parallel delegation fits independent tasks, not a writer waiting for research facts.
    • D — Unordered broadcast fits independent event handling, not a required evidence-before-writing dependency.
  5. Three independent source axes must be investigated and then compared. What should the coordinator do?
    • A. Run one source axis and assume it covers the others
    • B. Delegate independent axes in parallel, then aggregate results
    • C. Force each axis to wait for the prior one without a dependency
    • D. Let every spoke choose unrelated extra axes
    Answer

    Answer: B — Delegate independent axes in parallel, then aggregate results.

    Reason: Independence permits parallel work; comparison remains a coordinator aggregation task.

    • A — One axis fits a narrow question, not stated multi-axis coverage.
    • C — Sequential work fits genuine prior-result dependency, which the stem excludes.
    • D — Extra routing fits a design where spokes own selection, not a coordinator-managed plan.
  6. Three researchers receive the same broad market brief and return near-duplicate material. Which repair addresses root cause?
    • A. Give each a different agent name
    • B. Define non-overlapping scopes with include and exclude boundaries
    • C. Tell each to write a longer answer
    • D. Remove the coordinator from result aggregation
    Answer

    Answer: B — Define non-overlapping scopes with include and exclude boundaries.

    Reason: Explicit boundaries partition selected work and reduce duplicated coverage.

    • A — Different names fit identifying workers, but names do not define distinct research scope.
    • C — Longer answers fit a depth requirement, not duplicate-work prevention.
    • D — Removing aggregation fits a fully decentralized design, not a repair for overlap in coordinator work.
  7. A partition planner has supplied required partitions. The coordinator invents an extra angle before delegation. What is the design problem?
    • A. The coordinator has created a second routing owner
    • B. The coordinator has improved its static table
    • C. The planner has made one agent too fast
    • D. The extra angle proves partition coverage
    Answer

    Answer: A — The coordinator has created a second routing owner.

    Reason: When planning owns selection and partitioning, coordinator-added angles can conflict with that upstream decision.

    • B — Updating a static table fits presentation work, not ownership of routing decisions.
    • C — Performance tuning fits a measured latency problem, not conflicting partition selection.
    • D — An extra angle may be useful after replanning, but it does not itself prove coverage or preserve one owner.
  8. A generated partition covers no material question for the request. What should the planner do?
    • A. Keep it because every specialist should run
    • B. Omit the unneeded partition
    • C. Send it to every spoke for confirmation
    • D. Add it after the coordinator aggregates
    Answer

    Answer: B — Omit the unneeded partition.

    Reason: The plan should include only genuinely needed partitions.

    • A — Running every specialist fits a fixed completeness pipeline, not relevance-driven selection.
    • C — Broad confirmation fits a peer-review design, not avoiding an unnecessary partition.
    • D — Post-aggregation work fits an identified coverage gap, not an already-known irrelevant partition.
  9. A subagent lacks a constraint stated earlier by the user. What is the most likely cause in an isolated-agent design?
    • A. The coordinator did not pass the needed context in the handoff
    • B. The subagent automatically saw too much parent context
    • C. Parallel work made every message shared
    • D. A result aggregator replaced task instructions
    Answer

    Answer: A — The coordinator did not pass the needed context in the handoff.

    Reason: Isolated spokes require explicit task-relevant context and constraints.

    • B — Excessive inherited context fits a shared-context system, opposite to the isolated boundary in this stem.
    • C — Parallel scheduling fits independent timing, not automatic context sharing.
    • D — Aggregation fits combining completed outputs, not supplying missing initial instructions.
  10. A notification specialist needs only a notification action. Which boundary best follows least-scope delegation?
    • A. Give it every inventory, ordering, and notification tool
    • B. Give it only the notification tool and task context
    • C. Give it no task context so it stays independent
    • D. Let another spoke choose its tool set
    Answer

    Answer: B — Give it only the notification tool and task context.

    Reason: A bounded specialist receives the context and least capability needed for its assigned work.

    • A — Broad tools fit a generalist agent with cross-domain responsibility, not this narrow notification task.
    • C — No context fits a context-free utility, not a specialist that must perform a stated notification task.
    • D — Spoke-owned tool selection fits a decentralized system, not coordinator-controlled least-scope delegation.

Quick recall

Attempt each question before expanding it.

What work remains with a coordinator in hub-and-spoke design?

The coordinator decomposes, routes, decides context handoff, handles errors and observability, receives outputs, resolves conflicts, and aggregates a response.

What communication boundary separates a coordinator from spokes?

Spokes execute bounded assigned work and return through the coordinator; they do not directly coordinate with peer spokes in this pattern.

When should one agent answer a task?

Use one agent when a simple bounded factual task does not need separate dependent or independent subtasks.

What makes delegation sequential rather than parallel?

A later task needs an earlier result. The coordinator receives that result and hands required information to the next worker.

What condition makes parallel delegation appropriate?

Subtasks are independent, so none needs another subtask result before it can begin; the coordinator still aggregates returned outputs.

What is the difference between selection and partitioning?

Selection decides whether a dimension needs work. Partitioning divides selected work into distinct non-overlapping scopes.

What fields make a partition boundary inspectable?

Name the assigned worker, scope, and rules, including explicit include and exclude boundaries for the question it covers.

Why should a coordinator not add angles after a planner has selected partitions?

That creates two routing owners. The planner should own selection and partitioning; the coordinator should delegate the supplied partitions exactly once.

What must an explicit context handoff provide?

Provide the bounded task, relevant evidence or constraints, expected result shape, and task-required tool capability. Do not assume inherited conversation context.

Why should a subagent receive only assigned tools?

Least-scope tools constrain the worker to its delegated domain and make its boundary easier for the coordinator to inspect and reason about.
