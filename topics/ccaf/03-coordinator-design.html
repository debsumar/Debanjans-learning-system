Coordinator and multi-agent design

Route bounded work through one accountable hub, then combine results without assuming shared context.

Domain 1Agentic architecture and orchestrationWeight unverified
In one minuteSkills in scopeHub and spokeDelegation modePartitioningContext handoffMCQsQuick recall

In one minute

  • Keep routing, context sharing, error handling, and result aggregation with the coordinator; a spoke executes its assigned bounded task.
  • Use one agent for a simple factual task; use sequential delegation when dependency exists or coordinator policy requires order.
  • Use parallel delegation only when subtasks are independent and coordinator policy permits it; concurrent calls still need aggregation and review.
  • Partition selected work into non-overlapping scopes with include and exclude boundaries; different agent names alone do not prevent overlap.
  • Hand off required task context explicitly; demonstrated spokes received full job and resume context, while narrower boundaries require validation.

Skills in scope

This provisional mapping remains subject to the official guide when it is published.

  • Define coordinator responsibilities and hub-and-spoke communication boundaries.
  • Choose single, sequential, or parallel delegation from dependency and independence.
  • Design non-overlapping partitions with one routing owner and explicit scope boundaries.
  • Apply explicit context handoff and isolated sub-agent/tool boundaries.

Coordinator-owned hub and spoke

A coordinator receives the task, decomposes it, selects and routes bounded subagent work, passes needed context, receives results, and aggregates a response. The transcript pattern places routing, shared-context decisions, error handling, and observability at this hub rather than distributing them across peers.

DesignPrimary workWhat it does not establish
Generic task managerCreates, checks, completes, and lists tasks.Decomposition, worker selection, invocation, result collection, or aggregation.
CoordinatorDecomposes, selects, routes, delegates, collects, and aggregates bounded worker results.Independent spoke-to-spoke routing ownership.

A spoke is an assigned worker, not a peer router. In the transcript example, keyword scanner, deep evaluator, and red-flag detector supply bounded outputs; the coordinator selects and invokes them, then a score aggregator combines their results. Each spoke can return a result to the coordinator, but direct spoke-to-spoke communication is outside this hub-and-spoke boundary. That central path gives one accountable place to inspect traffic, resolve conflicts, and decide what happens next. This is architecture mechanics, not hiring advice.

ConfuseCoordinator means the hub that orchestrates, routes, shares context, and aggregates. A spoke is a bounded execution worker. A spoke does not replace the coordinator or directly coordinate with another spoke.
Common wrong turn

“Subagents should pass context directly to each other for speed.” — In this pattern, the coordinator owns context routing and result aggregation. A direct peer path removes the central control boundary.

Diagram: task context travels from coordinator to isolated spokes; each result returns to the coordinator for aggregation. The diagram does not show peer-to-peer spoke links.

Choose delegation from dependency and policy

Constraint to choice: use one agent when one bounded answer is enough. Use sequential delegation when a later worker needs an earlier result or coordinator policy requires an order. Use parallel delegation only when subtasks are independent and coordinator policy permits it, then combine their outputs.

ConfuseParallel means independent work can proceed without a prior result and when policy permits it. Sequential means a later task depends on an earlier result or coordinator policy requires order. Parallel is not a synonym for faster when either constraint remains.
  • Independent workers can still run sequentially: coordinator policy may require keyword scanner, deep evaluator, and red-flag detector in a stated order without skipping any.
  • Use dynamic selection from observed evidence. Skip a factual-match scan when it answers no real question; route a non-traditional background to a transfer-skills review; generated angles need not repeat a fixed pipeline.
  • Broader output is not proof of better judgement. Test representative data against human judgement, then adjust coordinator guidance or routing.

Parallel fan-out is a coordinator decision, not proof that every spawned agent has concurrent scheduling or visible internal progress. Keep the task dependency and policy boundary explicit, then inspect and combine returned work.

Common wrong turn

“Every specialist should run for completeness.” — Invoke a specialist only when it answers a relevant unanswered question; a mechanical pipeline can add cost and irrelevant output.

Partition selected work without overlap

Selection asks whether a dimension needs work. Research partitioning divides work already selected into distinct scopes. A useful partition names its worker, scope, and rules, including what it includes and excludes.

The coordinator owns decomposition, selection, routing, delegation, collection, and aggregation. Planning output can inform its choices, but does not become an independent routing owner; the coordinator may revise scope when evidence changes.

ConfusePartitioning divides selected work into non-overlapping partitions with scope rules. A partition has explicit scope rules. Selection decides whether work is needed at all. The coordinator owns both decisions and may use planning input without surrendering routing ownership.
Common wrong turn

“Different agent names make the research non-overlapping.” — Scope and include/exclude boundaries prevent overlap. Names alone do not state what each worker must avoid.

Explicit context handoff

Treat handoff as explicit. In the demonstrated workflow, every spoke receives full job and resume context; narrower context and spoke-level scope enforcement are controls to validate, not default behavior. Supply the task and relevant evidence or constraints rather than assuming a worker can infer an omitted boundary.

  1. Define the bounded task and the evidence needed to complete it.

    State what question the subagent answers and what remains outside its scope.

  2. Pass the demonstrated context and task-specific criteria.

    The demo gives each spoke the full job and resume context. Validate any narrower package or scope rule instead of assuming it is enforced.

  3. Receive a result through the coordinator.

    Keep the result associated with its task so the coordinator can inspect coverage and conflicts.

  4. Aggregate or route the next dependent step.

    The coordinator combines independent results or forwards the needed prior result to a later worker.

Architecture mechanics example, not hiring advice: a keyword scanner reports a required skill only when it appears literally in supplied resume evidence. It does not infer or extrapolate beyond that evidence boundary.

General least-privilege guidance, not a transcript rule: define an expected result shape and give a worker only task-needed tool capability when your system supports such controls. Validate that the implementation actually enforces the intended boundary.

A structured handoff is a context package for the next bounded action. Its breadth and enforcement must be explicit and testable, not assumed from the worker label.

MCQs

  1. A research worker and a review worker need to exchange a finding. Which path preserves hub-and-spoke control?
    • A. Research worker sends it directly to review worker
    • B. Coordinator receives it and passes needed context to review worker
    • C. Each worker broadcasts it to all workers
    • D. Review worker rereads the entire parent conversation
    Answer

    Answer: B — Coordinator receives it and passes needed context to review worker.

    Reason: The coordinator owns routing and explicit context handoff between spokes.

    • A — Direct delivery fits a peer-messaging architecture, not this coordinator-controlled hub-and-spoke boundary.
    • C — Broadcast can fit a deliberately shared event system, not bounded coordinator routing for this stem.
    • D — Rereading history does not create a coordinator-controlled explicit handoff.
  2. Which responsibility belongs to the coordinator rather than a bounded spoke?
    • A. Execute one assigned evidence lookup
    • B. Choose which subtasks to invoke and aggregate their results
    • C. Return an assigned report within its scope
    • D. Apply a validated tool boundary when the system supports it
    Answer

    Answer: B — Choose which subtasks to invoke and aggregate their results.

    Reason: Routing, decomposition, and aggregation are coordinator responsibilities.

    • A — An evidence lookup fits a spoke when the coordinator has assigned that bounded task.
    • C — A scoped report fits a spoke after it completes delegated work.
    • D — A validated tool boundary applies to individual worker capability, not coordinator-only orchestration.
  3. A request asks one straightforward factual question with no separate research dimensions. Which delegation mode fits first?
    • A. One agent
    • B. Sequential delegation
    • C. Parallel delegation
    • D. Three identical research partitions
    Answer

    Answer: A — One agent.

    Reason: A simple bounded factual task does not need coordination overhead.

    • B — Sequential delegation fits when a later task needs an earlier result or coordinator policy requires an order; neither condition applies in this stem.
    • C — Parallel delegation fits independent subtasks, which this single-question request lacks.
    • D — Multiple partitions fit broad work needing distinct scopes, not one simple fact.
  4. A writer can begin only after a researcher returns gathered facts. Which mode fits?
    • A. One agent with no handoff
    • B. Parallel delegation
    • C. Sequential delegation
    • D. Broadcast all tasks without order
    Answer

    Answer: C — Sequential delegation.

    Reason: The writer depends on the research output, so the coordinator must pass that result forward.

    • A — One agent fits when one bounded worker can complete the whole request without a required specialist handoff.
    • B — Parallel delegation fits independent tasks when coordinator policy permits it, not a writer waiting for research facts.
    • D — Unordered broadcast fits independent event handling, not a required evidence-before-writing dependency.
  5. Three independent source axes must be investigated and then compared, and coordinator policy permits concurrent calls. What should the coordinator do?
    • A. Run one source axis and assume it covers the others
    • B. Delegate independent axes in parallel, then aggregate results
    • C. Force each axis to wait for the prior one without a dependency or policy order
    • D. Let every spoke choose unrelated extra axes
    Answer

    Answer: B — Delegate independent axes in parallel, then aggregate results.

    Reason: Independence plus coordinator policy permission permits parallel work; comparison remains a coordinator aggregation task.

    • A — One axis fits a narrow question, not stated multi-axis coverage.
    • C — Sequential work can fit a genuine prior-result dependency or policy order, neither of which the stem states.
    • D — Extra routing fits a design where spokes own selection, not a coordinator-managed plan.
  6. Three researchers receive the same broad market brief and return near-duplicate material. Which repair addresses root cause?
    • A. Give each a different agent name
    • B. Define non-overlapping scopes with include and exclude boundaries
    • C. Tell each to write a longer answer
    • D. Remove the coordinator from result aggregation
    Answer

    Answer: B — Define non-overlapping scopes with include and exclude boundaries.

    Reason: Explicit boundaries partition selected work and reduce duplicated coverage.

    • A — Different names fit identifying workers, but names do not define distinct research scope.
    • C — Longer answers fit a depth requirement, not duplicate-work prevention.
    • D — Removing aggregation fits a fully decentralized design, not a repair for overlap in coordinator work.
  7. Planning output proposes partitions, but new evidence changes the request before delegation. Which responsibility remains with the coordinator?
    • A. Decide whether to keep, revise, and route the proposed partitions
    • B. Treat planner output as immutable routing ownership
    • C. Let each spoke select unrelated extra partitions
    • D. Delegate every proposed partition without checking relevance
    Answer

    Answer: A — Decide whether to keep, revise, and route the proposed partitions.

    Reason: Planning output can inform the coordinator, but the coordinator remains accountable for decomposition, selection, routing, delegation, collection, and aggregation.

    • B — A planner can supply input, but it does not become an independent routing owner.
    • C — Spokes execute bounded assigned work; unrelated selection remains coordinator-owned.
    • D — Relevance and scope remain coordinator decisions, especially when evidence changes.
  8. A generated partition covers no material question for the request. What should the coordinator do?
    • A. Keep it because every specialist should run
    • B. Omit the unneeded partition
    • C. Send it to every spoke for confirmation
    • D. Add it after the coordinator aggregates
    Answer

    Answer: B — Omit the unneeded partition.

    Reason: The coordinator should select only genuinely needed partitions.

    • A — Running every specialist fits a fixed completeness pipeline, not relevance-driven selection.
    • C — Broad confirmation fits a peer-review design, not avoiding an unnecessary partition.
    • D — Post-aggregation work fits an identified coverage gap, not an already-known irrelevant partition.
  9. A subagent lacks a constraint stated earlier by the user in a workflow that uses explicit handoff. What is the most likely cause?
    • A. The coordinator did not pass the needed context in the handoff
    • B. The subagent automatically inherited all parent context
    • C. Parallel work made every message shared
    • D. A result aggregator replaced task instructions
    Answer

    Answer: A — The coordinator did not pass the needed context in the handoff.

    Reason: Required context must be handed off explicitly. The demonstrated spokes received full job and resume context; narrower packages are controls to validate, not defaults.

    • B — The demonstrated full context is passed explicitly by the coordinator, not automatically inherited.
    • C — Parallel scheduling fits independent timing, not automatic context sharing.
    • D — Aggregation fits combining completed outputs, not supplying missing initial instructions.
  10. A notification specialist needs only a notification action. If the system supports tool boundaries, which general least-privilege control should be validated?
    • A. Give it every inventory, ordering, and notification tool
    • B. Give it task context and only the notification tool capability
    • C. Give it no task context so it stays independent
    • D. Let another spoke choose its tool set
    Answer

    Answer: B — Give it task context and only the notification tool capability.

    Reason: Least privilege is general guidance, not a demonstrated transcript fact. Where tool controls exist, define the needed capability and validate that the implementation enforces it.

    • A — Broad tools exceed the stated task and do not test a narrow capability boundary.
    • C — No context does not support a specialist that must perform a stated notification task.
    • D — The coordinator remains accountable for routing and handoff decisions; tool-boundary enforcement still requires validation.

Quick recall

Attempt each question before expanding it.

What work remains with a coordinator in hub-and-spoke design?

The coordinator decomposes, routes, decides context handoff, handles errors and observability, receives outputs, resolves conflicts, and aggregates a response.

What communication boundary separates a coordinator from spokes?

Spokes execute bounded assigned work and return through the coordinator; they do not directly coordinate with peer spokes in this pattern.

When should one agent answer a task?

Use one agent when a simple bounded factual task does not need separate dependent or independent subtasks.

What makes delegation sequential rather than parallel?

A later task needs an earlier result, or coordinator policy requires an order. The coordinator receives the result and hands required information to the next worker when a prior result is needed.

What condition makes parallel delegation appropriate?

Subtasks are independent and coordinator policy permits parallel delegation, so none needs another subtask result before it can begin; the coordinator still aggregates returned outputs.

What is the difference between selection and partitioning?

Selection decides whether a dimension needs work. Partitioning divides selected work into distinct non-overlapping scopes.

What fields make a partition boundary inspectable?

Name the assigned worker, scope, and rules, including explicit include and exclude boundaries for the question it covers.

Who owns decomposition, selection, and routing when planning input proposes partitions?

The coordinator owns decomposition, selection, routing, delegation, collection, and aggregation. Planning output may inform those decisions, but never becomes an independent routing owner.

What must an explicit context handoff provide?

Make the handoff explicit: provide the bounded task and relevant evidence or constraints. The demonstrated spokes received full job and resume context; narrow context, result-shape, and tool boundaries are controls to define and validate, not defaults to assume.

How should least-privilege tool boundaries be treated for a subagent?

Least privilege is general guidance, not a demonstrated transcript rule. Where the system supports tool controls, give task-needed capability and validate that the intended boundary is actually enforced.
